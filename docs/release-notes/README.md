# Playlist Canvas 릴리즈 노트 개편

기존 GitHub Releases 19개(1.0.0.0 ~ 1.3.1.4)의 설명을 일반 사용자 관점에서 다시 작성했습니다.

## 작성 원칙
- 새 기능과 실제 사용자의 이점을 먼저 소개합니다.
- 내부 함수 이름, 스레드 구조, 개발 도구 및 테스트 상세 대신 사용자가 체감할 변경 사항을 적습니다.
- 기존의 베타 안내, FFmpeg 의존성, 이전 버전의 버그·제한 사항과 저장 공간 경고는 유지합니다.
- 지나친 성능 일반화나 확인되지 않은 기능 추가를 피합니다.
- 기존 Git 태그, 릴리즈 제목·날짜 및 다운로드 파일은 변경하지 않습니다.

## 수정안 구성
- 1.3.json: 1.3.0.0 ~ 1.3.1.4
- 1.2.json: 1.2.0.0 ~ 1.2.0.8
- 1.0-1.1.json: 1.0.0.0, 1.0.1.0, v1.0.2, 1.1.0.0

JSON의 각 키는 실제 GitHub Release 태그입니다. v1.0.2는 릴리즈 제목과 달리 태그 이름이 v1.0.2이므로 그대로 사용합니다.

## 실제 GitHub 릴리즈에 반영하기

이 PR을 합친 뒤 GitHub 저장소의 **Actions → Update published release descriptions → Run workflow**에서 진행하세요.

1. 먼저 mode: check로 실행하여 수정 대상 19개를 확인합니다. 이 모드는 실제 릴리즈를 수정하지 않습니다.
2. 검토가 끝났다면 같은 워크플로를 mode: apply로 실행합니다.
3. 실행이 끝나면 워크플로의 요약에서 변경 결과를 확인할 수 있습니다.

변경 전의 릴리즈 설명은 실행 과정에서 자동으로 백업되며 Actions의 실행 결과(Artifacts)에서 90일 동안 내려받을 수 있습니다. 릴리즈가 없거나 태그를 찾지 못하면 실제 반영 이전에 중단합니다.

**변경 대상은 오직 릴리즈 설명(body)뿐입니다.** 버전 태그, 릴리즈 이름, 파일 첨부물 및 공개 상태는 그대로 유지됩니다.

필요하면 저장소 루트에서 python3 tools/sync_release_notes.py --mode check로 확인할 수도 있습니다. GitHub API 인증용 GH_TOKEN 또는 GITHUB_TOKEN 환경 변수가 필요합니다.

## 역사적 안내 주의
- 1.2.0.6: AutoMix 설치본 누락 문제는 이후 1.2.0.7에서 고쳐졌다는 안내를 보존했습니다.
- 1.0.1.0 ~ 1.2.0.2: 당시 내보내기의 큰 임시 공간 사용에 대한 주의 문구를 유지했습니다. 현재 버전의 저장 공간 사용량으로 일반화하면 안 됩니다.
- 1.0.0.0: 첫 배포 당시에는 자동 업데이트 기능이 없었습니다.
