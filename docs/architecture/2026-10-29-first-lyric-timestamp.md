# 첫 가사가 곡 시작부터 활성화되는 문제

## 확인 및 원인

실행 중인 Playlist Canvas의 ‘랩스타’ 곡 정보/설정 → 가사 설정을 computer-use로 읽어 확인했다. 첫 LRC 타임코드는 25.180초인데, 재생 위치 00:00에서 첫 문장이 현재 가사 영역에 강조되어 있었다. 실행 중인 앱의 프로젝트에는 저장되지 않은 변경이 있으므로 앱 상태를 유지했다.

`LyricsService.display_cue_index()`는 첫 가사를 미리 보여주기 위한 배치 기준으로 0을 반환한다. 곡 정보 창은 이를 현재 가사로 표시했고, 공용 프레임 상태의 일반 LRC 실시간 모드는 시작 여부와 관계없이 해당 줄을 활성화했다. 첫 줄의 전환 시작 시각도 곡 시작 이전으로 강제하고 있었다.

## 수정

- 공용 상태에 `before_first`를 추가해 배치 기준과 실제 활성 상태를 구분한다. 타임코드 이전에는 현재 가사가 없고 전환/강조도 시작되지 않는다.
- 시작 전 가사는 다음 가사 스타일을 사용한다. 완료된 가사를 붙잡아 두는 이전 가사 스타일과 구분하며, 기존 줄 배치는 유지한다.
- 지연된 첫 가사는 실제 시작 시각부터 전환한다. 0초에 이미 시작한 첫 줄과 첫 줄 이후의 일반 가사 유지 동작은 보존한다.
- LRC 실시간 모드에서도 설정된 첫 가사 대기 표시를 사용한다. 기존 중간 간주 처리는 유지한다.
- 음수 보정으로 가사 시간이 아직 음수인 경우에도 첫 줄이 조기에 활성화되지 않도록 한다.
- 곡 정보 창에는 ‘첫 가사 대기 · 00:25.180’을 표시하고, 첫 문장을 다음 가사 영역에 둔다. 타이밍 보정과 이전 위치로 되돌리기도 같은 기준을 사용한다.
- 내보내기 캐시 키에 대기 상태를 포함하고, 캡처 후 그래픽 요소의 임시 상태를 복원한다. 프로젝트 저장 형식과 원본 가사 내용은 변경하지 않는다.

## 검증

`tests/test_lyrics_first_cue.py`는 25.179초/25.180초 경계, 일반/실시간 모드, 양수·음수 보정, 0초에 이미 시작한 줄, 되감기, 곡 정보 창, 대기 표시, 미리보기/내보내기 동등성, 프레임 병합 및 원본/임시 상태 복원을 검증한다. 기존에 첫 줄을 0초부터 활성화하도록 기대하던 테스트도 새 동작에 맞췄다.

`work/lyrics-first-cue-2026-10-29/compare_frames.py`는 이 수정 직전 작업 트리의 렌더러/상태 함수와 수정 후를 동일 프로세스에서 비교한다. `apply_studio_style()`로 실제 앱이 사용하는 시스템 글꼴을 등록했다. 비교 조건은 8개 효과 × 4방향 × 기본/고급 설정 × 640×360/1920×1080 × 8시점, 총 1,024프레임이다. TTML 단어 타이밍, 한영/이모지/여러 줄, 인트로와 줄별 스타일/블러가 포함된다.

- 첫 가사 시작 이후 896개 프레임 모두 크기·포맷·픽셀 SHA-256이 동일했다.
- 시작 전 128개 프레임 중 112개는 의도한 다음 가사 스타일 변경으로 달라졌고, 나머지 16개는 동일했다. 시작 이후의 변경은 없었다.
- 곡 정보 창 대기 UI를 한국어로 렌더링해 확인했다. `work/lyrics-first-cue-2026-10-29/lyrics-preview-0.png`.
- 가사·TTML·프레임 상태·내보내기 프레임 동등성·메인 창 미리보기·TTML 편집 흐름 19개 모듈의 테스트 294개가 모두 통과했다. `work/lyrics-first-cue-2026-10-29/tests-final.json`.

비교는 압축 전 렌더링 결과에 대한 검증이다. 모든 프로젝트와 인코더 조합의 완성 영상 파일을 바이트 단위로 비교한 검증은 아니다. 실행 중인 기존 프로세스에는 코드를 주입하거나 자동 재시작하지 않았다. 소스 수정 반영에는 앱 재실행이 필요하다.
