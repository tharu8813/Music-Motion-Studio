# 실제 로컬 LLM 가사 번역 품질 평가 (2026-11-19)

## 목표

프롬프트/모델 변경 후 품질이 개선됐다는 주장을 가짜 모델(Mock) 통과 건수나 JSON 형식 성공률만으로 하지 않도록, 실제 Ollama 또는 LM Studio에서 반복 실행 가능한 평가 세트를 둔다.

이 평가 세트는 **공개된 곡의 가사를 복제하지 않은 독자적인 테스트 문장** 8개 시나리오로 구성한다: 부정 표현, 힙합/R&B 슬랭, 한국어·영어 혼합, 반복 후렴, 중의성, 나뉜 문장, 한 큐 내부 줄바꿈, 고유명사·시제.

## 로컬 실행

프로젝트 루트에서 로컬 LLM 서버를 실행하고 이미 설치한 모델을 선택한다.

    python scripts/benchmark_lyrics_translation.py --provider ollama --model qwen3.5:9b --output work/qa-qwen9b.json
    python scripts/benchmark_lyrics_translation.py --provider lmstudio --model MODEL_ID --endpoint http://localhost:1234/v1 --limit 3 --output work/qa-lmstudio.json

스크립트는 각 시나리오를 **현재 앱의 실제 2단계 가사 번역 코드**로 번역한다. 한 시나리오의 결과는 다음 시나리오의 번역 문맥으로 넘어가지 않는다.

출력 JSON에는 원문, 번역 결과, 실행 시간, 감지된 번역 누락/문자 혼입, 반복 구절 출력 차이, 사람 검토 질문이 포함된다. API 키·프로젝트 가사·모델의 미가공 내부 응답은 기록하지 않는다. 출력은 임시 파일에 먼저 기록한 뒤 교체하여 중간에 쓰기 실패가 나더라도 기존 보고서를 임의로 지우지 않는다.

## 평가 해석

- 자동 플래그는 **구조 및 제한적인 문자열 기반 위험 징후**이다. 사람의 번역 품질 평가 점수가 아니다.
- 사람이 각 행의 부정/시제/슬랭/맥락/자연스러움을 1~5점으로 평가하고 원문과 함께 확인한다.
- 모델별 3회 반복 실행으로 응답 성공률, 재시도 여부, 실행 시간 및 사람 평가의 분포를 비교한다.
- 실패하는 번역의 문체나 의미를 직접 비교해야 하며, 자동 플래그 0개라는 이유만으로 정확하다고 판정하지 않는다.
- 실제 Qwen3.5:9B, RAM/VRAM 사용량, 실제 Windows 로컬 서버의 작동성은 자동 CI 테스트 대신 사용자 로컬 환경 실측이 필요하다.

## 자동 검증 범위

`tests/test_lyrics_quality_benchmark.py`는 실제 모델을 호출하지 않고 시나리오 목록, 결과 구조, 사람 검토 설명, 언어 방향, 실패 보존, 반복 표현 차이 및 파일 출력을 검증한다.
