# 내보내기 후속 최적화 — 2026-10-26

추가 변경은 가사 블러의 임시 배열, 가사 이미지 캐시, 소비가 끝난 프레임의 수명에
한정했다. **전체 내보내기의 유의미한 추가 속도 향상은 확인하지 못했다.** 앞서 적용한
CFR 중복 캡처 생략은 그대로 유지한다.

## 변경과 검증

- `SourceItem._blurred_raster`: 반올림과 clipping을 float 배열 안에서 수행하고
  uint8 이미지로 직접 복사한다. 기존 순서와 결과를 유지하면서 중간 배열을 줄였다.
- 가사 블러 이미지 캐시: 사용한 항목을 최신 위치로 옮겨 자주 쓰는 가사가 먼저
  제거되지 않게 했다. 상한은 기존 96개다.
- `BoundedExportPipeline`: 다음 입력을 기다리기 전에 소비한 항목의 참조를 해제한다.
  빈 큐에서 대기하는 동안 마지막 이미지가 남지 않는지 회귀 검사했다.

캐시 교체와 float 변환 경계값에 대한 테스트를 추가했다. 출력 크기, FPS, 블러 반경,
품질 설정, 장면 배치, 취소 처리와 큐 용량은 바꾸지 않았다.

내보내기·가사·텍스트·도형·큐 관련 회귀 검사 27개 모듈에서 386개 테스트를 실행해
실패/오류 없이 완료했다(조건부 skip 9개). 기록은
`work/optimization-round2/regression-tests.json`에 있다. 변경 파일의 `compileall`과
`git diff --check`도 통과했다.

별도 배포 경로는 `dist/export-optimized-v2/Playlist Canvas`다. 배포 필수 파일 검사와
실행 파일 안의 Python 코드 확인으로 세 가지 변경의 포함 여부를 확인했다.
격리된 작업 폴더에서 새 실행 파일의 `--smoke-test`도 종료 코드 0으로 완료했다.
Inno Setup 설치 파일도 빌드했다:
`output-setup/export-optimized-v2/Playlist Canvas-1.3.1.3-export-optimized-v2-setup.exe`.
현재 설치된 앱에는 자동으로 적용하지 않았다.

## 측정 결과

| 범위 | 수정 전 | 수정 후 | 해석 |
|---|---:|---:|---|
| 캐시된 단색 블러 색상 변환 20회, 8회 교대 측정의 중앙값 | 0.27508초 | 0.18986초 | 이 연산만 약 31.0% 단축 |
| 위 연산의 Python/NumPy 추적 메모리 peak | 21,602,452 bytes | 7,268,436 bytes | 약 66.4% 감소; 앱 전체 RSS가 아님 |
| IVY 첫 곡을 20초로 줄인 실제 NVENC 내보내기 | 51.046초 | 50.781초 | 단일 쌍, 약 0.5% 차이로 추가 속도 향상 근거가 부족 |

블러 미세 벤치마크는 1500×300 float coverage를 캐시해 색상만 다시 구성하는 경우다.
실제 가사의 coverage 크기와 캐시 적중률에 따라 효과가 달라지며, 앱 전체 성능으로
환산할 수 없다. 두 구현의 출력 픽셀은 동일했다.

실제 내보내기는 1920×1080, 60 FPS, NVENC, CRF 14, medium, AAC 320k로 실행했다.
수정 전후 1,200개 디코딩 프레임과 타임스탬프의 해시가 모두 같았다.
IVY 30–33초 구간의 세 Canvas 밴드도 각각 180프레임의 해시가 같았다.
이 구간 캡처 시간은 전 6.572/5.609초, 후 7.564/5.494초로 편차가 커 추가 속도
향상의 근거로 사용하지 않았다. 기존 CFR 최적화가 켜진 상태끼리 비교한 수치다.

측정 환경은 앞선 [IVY 진단](ivy-export-profile-2026-10-26.md)과 같다. Qt offscreen,
작업 복사본과 격리된 설정을 사용했다. 현재 작업은 원본 IVY 프로젝트를 저장하지 않는다.
다른 사용자 앱의 부하는 통제하지 않았으며, 21분 전체와 설치본 UI 내보내기는 재측정하지 않았다.

## 채택하지 않은 실험

가사 래스터 영역 축소는 소수점 변환/회전에서 출력이 달라져 제외했다. QImage 버퍼 재사용,
Python 스레드 전환 주기 변경은 전체 시간 개선이 확인되지 않았다. 시각화 별도 프로세스는
단일 비교에서 작은 차이만 보여 IPC·종료·패키징 변경까지 제품에 넣지 않았다.
큰 폭의 추가 개선은 Canvas 렌더링과 여러 입력의 동기화 구조를 별도로 다뤄야 한다.

원본 수치와 프레임 해시:
[2026-10-26-export-blur.json](benchmarks/2026-10-26-export-blur.json).
실험 스크립트와 전체 출력은 `work/optimization-round2/`, `work/ivy-export-profile/`에 있다.
