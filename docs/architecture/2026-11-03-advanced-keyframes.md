# 베지어 그래프와 추가 속성 키프레임

> 현재 기본 편집 흐름은 [곡 시작·곡 끝 사용자 지정 편집기](2026-11-03-custom-motion-editor.md)로 변경되었다. 이 문서의 범용 편집 화면은 저장된 이전 데이터의 호환용이다.

## 사용 방법과 지원 범위

하단 타임라인에서 `키프레임 편집`을 선택한다. 다음 키프레임이 있는 시작점 하나를 선택한 뒤 `그래프`를 누르면 해당 구간을 편집한다. P1·P2 드래그, 네 좌표 입력, 기본·선형·서서히 시작·서서히 종료·부드럽게·반동 프리셋을 제공한다. `적용`은 한 번의 실행 취소로 되돌릴 수 있다. `취소`는 프로젝트를 수정하지 않는다. 숫자 보간 선택 상자의 `베지어`도 같은 평가기를 사용한다.

공통 다섯 속성인 위치 X/Y·크기·회전·투명도에 다음 열 개 속성을 추가했다. 실제 지원하는 속성만 레인과 속성창 다이아몬드에 표시한다.

| 추가 속성 | 지원 범위 |
| --- | --- |
| 너비, 높이 | 이미지·텍스트·도형·진행 막대·시간·앨범 커버·로고·워터마크·배경·가사·곡 목록·Now Playing |
| 블러 | 이미지·앨범 커버·로고·워터마크·일반 이미지/앨범 아트 배경. 단색 배경과 앰비언트 앨범 아트 배경 제외 |
| 글자 크기 | 텍스트·시간·가사·곡 목록·Now Playing |
| 모서리 반경 | 위 Canvas 소스 유형. 실제 모양·마스크에 따라 눈에 보이는 효과는 달라짐 |
| 테두리 두께 | 도형 |
| 그림자 투명도, 흐림, X, Y | 위 Canvas 소스 유형. 그림자 활성화 상태에서 표시됨 |

앨범 커버는 기존 정사각형 제약을 유지한다. 너비·높이를 함께 키프레임으로 지정하면 너비가 기준이며, 높이만 지정하면 너비도 같은 값으로 평가한다. 추가 속성은 기존 속성창 범위로 제한한다. 기본값 편집·자동 키프레임·전체 영상/특정 곡/모든 곡 개별·복사·붙여넣기 정책은 공통 속성과 같다.

영상과 오디오 반응형 소스는 공통 다섯 속성의 키프레임과 베지어를 지원한다. 이 유형에는 위 열 개 추가 속성을 제공하지 않는다. 색상·불리언·텍스트 내용·파일 경로 키프레임도 이번 범위에 포함되지 않는다.

## 평가·저장·내보내기

`Keyframe.bezier`는 `(x1, y1, x2, y2)`이며 이전 프로젝트의 기본값은 `(0.25, 0.1, 0.25, 1)`이다. X는 0–1, Y는 -2–3 범위다. 잘못된 좌표는 기본값으로 정규화한다. 제어점은 점의 이동·수치 편집·복사·저장·실행 취소 후에도 보존한다.

3차 베지어의 X 좌표를 28회 이분 탐색으로 역산한 뒤 같은 매개변수의 Y를 평가한다. Y를 직접 시간으로 대입하는 근사식을 사용하지 않는다. Y의 반동을 허용하되 최종 값은 속성 범위로 제한한다. FFmpeg도 같은 반복 횟수와 제어점을 사용한다. 픽셀별 알파 평가에서는 시각별 계산을 캐시해 반복 비용을 줄이며, 첫 프레임의 초기 캐시도 구분한다.

영상의 회전용 버퍼는 베지어 Y의 도함수 근으로 구간 내부의 최대 크기를 구한다. 끝점보다 커지는 반동을 포함해 출력 잘림을 방지한다. 전체 영상·곡별 평가와 크로스페이드의 화면 소유권은 기존 공통 엔진을 따른다.

추가 속성은 렌더링용 Source 복사본에 적용한다. 그림자 변경에는 별도 Shadow 복사본을 쓴다. 편집 Canvas의 현재 포즈와 내보내기 시각을 구분하고, 캡처 후 소스 참조·변형 원점·이미지 필터·위치와 상태를 복원한다. 다른 곡으로 캡처할 때 편집 화면의 블러가 남지 않도록 기본 필터도 복원한다. 프로젝트 캔버스 크기를 조정하면 추가 크기·글꼴·테두리·그림자 점도 기존 기본값과 같은 비율로 조정한다.

Canvas 추가 속성은 기존 프레임 출력 경로를 사용하고, 영상·오디오 공통 속성은 FFmpeg 동적 수식으로 출력한다. GPU 미리보기는 NVIDIA OpenGL 합성·표시 경로를 검증한다. 이 검증은 모든 효과가 GPU 셰이더로 실행되거나 영상 디코더가 하드웨어 디코딩한다는 뜻이 아니다.

## 자동 검증과 UI 확인

- `tests/test_keyframe_advanced.py`: 베지어 역산·잘못된 입력·반동 한계·뱅크 저장·추가 속성 원본 복원·실제 픽셀 변화·내보내기 프레임 일치·곡 전환 블러 복원·그래프 드래그/취소·실제 GPU 프레임 비교.
- `tests/test_keyframe_workspace.py`: 그래프 적용 한 번의 Undo/Redo와 취소의 비변경 동작.
- `tests/test_keyframe_rendering.py`: 모든 보간과 실제 FFmpeg 수식 비교, 사용자 베지어의 MP4 인코딩 후 위치·회전·알파 및 반동 출력 비교.
- `tests/keyframe_runtime_fixture.py`: 실제 MP4에 베지어 공통 속성과 도형·텍스트·이미지의 열 개 추가 속성을 함께 적용하는 연속 재생 장면.
- `tests/test_canvas_process_stream.py`: 사용자 베지어·너비·글자 크기·테두리·그림자를 직렬화해 별도 Qt 프로세스에서 렌더링하고 실제 FFmpeg 파이프를 통과시킨 불투명/투명 프레임이 단일 프로세스와 바이트 단위로 일치하는지 검사.

실제 Qt 위젯을 한국어 100%·영어 150%로 렌더링해 그래프의 제어점·좌표·버튼을 확인했다. 960×520 작업공간에서 레인과 숫자 도구의 겹침을 검사하고, 확대·축소·초기화를 `⋯` 메뉴로 옮겨 편집 버튼을 읽을 수 있게 했다. 캡처는 `work/bezier-graph-ko-1.png`, `work/bezier-graph-en-1.5.png`, `work/keyframe-ui-after-short-1.png`다. 물리 입력 장치와 화면 읽기 프로그램의 수동 검증은 포함하지 않는다.

## 실제 GPU·장시간 검증 실행

Windows 네이티브 Qt 플랫폼과 실제 FFmpeg를 사용한다. 일상 회귀 실행에서는 긴 테스트를 자동으로 실행하지 않는다.

```powershell
$env:QT_QPA_PLATFORM='windows'
$env:PLAYLIST_CANVAS_TEST_FFMPEG=(Get-Command ffmpeg).Source
$env:PLAYLIST_CANVAS_RUN_PREVIEW_SOAK='1'
$env:PLAYLIST_CANVAS_PREVIEW_SOAK_KEYFRAMES='1'
$env:PLAYLIST_CANVAS_PREVIEW_SOAK_SECONDS='600'
$env:PLAYLIST_CANVAS_PREVIEW_SOAK_BACKEND='gpu_layers'
.\.venv\Scripts\python.exe -m unittest tests.test_real_video_preview_performance.RealVideoPreviewPerformanceTests.test_long_real_mp4_preview_remains_bounded_and_responsive tests.test_real_video_preview_performance.RealVideoPreviewPerformanceTests.test_repeated_open_pause_seek_resume_close_releases_preview -v
```

테스트는 워밍업 후 메모리 기준점을 잡고 영상 루프·디코더 프레임·타임라인 진행·이벤트 루프 응답·GPU 모드 유지·프로젝트 원본 보존을 검사한다. 연속 테스트 후 별도 10회 열기·일시 정지·탐색·재생·종료에서 텍스처 메모리와 디코더·작업자 해제를 검사한다. 640×360 Canvas와 적응형 미리보기 해상도를 사용한다. 모든 대형 프로젝트·고해상도 조합의 안정성 보장을 의미하지 않는다.

### 2026-11-03 실제 실행 결과

Windows, NVIDIA GeForce RTX 5060(8,151 MiB, 드라이버 621.01), NVIDIA OpenGL 3.3, PySide6 6.12.0, FFmpeg 9.0.2에서 실행했다. `PREVIEW_DEVICE`의 실제 OpenGL vendor/renderer로 NVIDIA 경로임을 확인했다.

| 검증 | 측정 결과 |
| --- | ---: |
| 베지어·열 개 추가 속성을 포함한 4개 요소 연속 재생 | 600초, 통과 |
| 워밍업 이후 디코더 수락 프레임 | 11,938 |
| GPU에서 표시한 새 장면 프레임 | 17,482 |
| 디코더 압력 드롭 / GPU 정지 감지 | 0 / 0 |
| 이벤트 루프 heartbeat / 최대 간격 | 5,486회 / 138.53ms |
| 프로세스 RSS 최고 증가 / 종료 시 증가 | 37.71 / 31.44 MiB |
| GPU 텍스처 할당량 | 778,752바이트, 시작/종료 동일 |

실제 GPU 텍스처 및 고급 키프레임 테스트 **24개**가 건너뜀 없이 통과했다. GPU 프레임버퍼와 Canvas의 네 시각을 비교해 채널별 평균 오차 0.5 미만, 99백분위 오차 3 미만을 확인했다. 별도 Qt 프로세스·FFmpeg 파이프 검사 **7개**도 모두 통과했다.

원본 로그는 `work/keyframe-gpu-600s.log`, `work/keyframe-gpu-parity-final.log`, `work/keyframe-process-export-final.log`다. 실제 측정 JSON과 모듈별 결과는 [검증 기록](benchmarks/2026-11-03-keyframes.json)에 저장했다.

전체 179개 모듈을 새 프로세스로 실행한 뒤, FFmpeg 환경 변수가 없어 건너뛴 15개 모듈의 210개 검사를 실제 FFmpeg로 재실행했다. 네이티브 GPU·실제 미디어·추가 회귀 결과로 해당 모듈/검사 결과를 교체했으며 중복 실행을 더하지 않았다. 최종 집계는 **2,301개 중 2,290개 통과, 11개 건너뜀, 실패 0개**다. 건너뛴 항목은 선택 설치형 Beat This! 모델 3개·Sonara 모델 2개와 Windows에서 실행하지 않는 POSIX FIFO 검사 6개다.

인증 테스트의 최초 샌드박스 실행은 localhost 모의 콜백 연결이 WinError 10013으로 막혀 시간 제한에 걸렸다. 해당 7개 검사는 샌드박스 밖에서 모의 응답을 사용해 재실행했고 모두 통과했다. 이 재실행과 원본 실행의 구분도 검증 JSON에 남겼다. `compileall`과 `git diff --check`도 통과했다.
