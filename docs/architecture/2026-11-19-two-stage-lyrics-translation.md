# LLM 가사 번역 2단계 파이프라인 (2026-11-19)

## 핵심 변경

기존에는 매 번역 배치에서 일부 원문을 참고 문맥으로 제공했다. 이제 LLM 전용 경로는 하나의 작업 안에서 다음 2단계를 수행한다.

1. **곡 전체 분석:** 모든 비어 있지 않은 가사 큐를 원본 순서와 ID로 한 번 전달한다. 화자/수신자, 감정 변화, 후렴, 은유, 코드 스위칭, 번역문 톤, 반복 용어의 실용적인 가이드를 구조화된 JSON으로 생성한다. 이 단계에서는 가사 번역을 생성하지 않는다.
2. **큐별 번역:** 위 계획을 모든 번역 배치에서 동일하게 참고한다. 앞뒤 원문/이전 배치 번역과 함께 제공하여 문맥과 표현을 유지한다. 출력 계약은 기존 `{"translations":[{"id":0,"text":"..."}]}` 형식이며 ID, 줄바꿈 및 부분 성공 검사는 변경하지 않는다.

전용 로컬 번역 모델(`local_nmt`)에는 LLM 프롬프트를 보내지 않는다.

## 정확도와 일관성

- 직역으로 문장이 어색해지는 문제를 줄이기 위해 기본 원칙을 **의미에 충실한 자연스러운 번역**으로 조정했다.
- 화자, 부정, 시제, 감정의 강도, 은유, 슬랭·비속어, 인명, 의도적인 중의성을 보존하도록 지시한다.
- 원문에 없는 관계/동기/감정을 만들어내지 않고, 확실하지 않은 가사는 모호성을 유지한다.
- 반복 표현은 동일 의미일 때만 일관된 번역을 권장한다. 분석 모델이 제시한 용어는 실제 전체 원문에 등장하는 경우에만 사용한다.
- 모델의 분석 결과와 사용자 문체 요청은 참고 데이터로 처리한다. 출력 형식 변경/다른 ID 번역 지시를 따르지 않는다.

## 비용·문맥·예외

- 분석 요청이 번역 시작 전에 **한 번 추가**되므로 클라우드 API 비용과 처리 시간이 증가할 수 있다.
- 통상적인 가사는 모두 전달하지만, 첫 단계 입력의 상한은 **48,000자(비어 있지 않은 큐 본문 합계)**이다. 이를 넘거나 분석 결과가 유효하지 않으면 상태 메시지를 보여주고 **기존 문맥 번역**으로 안전하게 전환한다. 전체 가사를 일부만 전송하고 전체를 분석한 것처럼 표시하지 않는다.
- 분석이 성공한 경우 별도로 반복하는 `song_context`는 클라우드 2,400자/로컬 LLM 1,200자로 축소한다. 분석 실패 시 기존 9,000자/3,500자 문맥 정책을 유지한다.
- 번역 배치는 기존 클라우드 최대 20큐/4,000자, 로컬 LLM 최대 12큐/1,800자 정책을 유지한다.
- 선택한 일부 행만 재번역해도 **1단계에서는 곡 전체 원문을 모델에 전송**한다. 클라우드 제공자의 데이터 전송 고지를 UI에 명시했다.
- 결과가 JSON을 충족하지 않거나 ID/줄바꿈이 잘못되면 기존처럼 오류로 표시하고 기존 초안과 부분 완료 행을 보존한다. 번역 분석은 실행 중에만 메모리에 보관하며 프로젝트/초안에 영속 저장하지 않는다.

## 로컬 모델 추천

앱 내 **가사 번역용 LLM 추천·다운로드**로 들어가면 가사 번역 적합성 필터가 기본 선택된다. 이 모델들은 자동 번역 품질 평가 순위가 아닌 **사용 목적별 후보 목록**이다.

| 모델 | 사용 시나리오 | 참고 다운로드 크기 |
|---|---|---|
| `qwen3.5:9b` | 기본 추천: 문맥·문체와 실행 부담 균형 | 약 6.6~7.6GB |
| `qwen3.5:4b` | 경량 테스트, 빠른 응답 우선 | 약 3.3~4.0GB |
| `qwen3.5:27b` | 높은 메모리 사양, 복잡한 문맥 | 약 17~20GB |
| `gemma3:4b`, `qwen3:8b` | 다른 계열과 번역 결과 비교 | 모델 페이지 참고 |

Ollama 공식 카탈로그에서 모델을 선택해 기존 다운로드·진행률·취소·이어받기 기능을 활용한다. 다운로드 크기는 실제 필요 RAM/VRAM과 다르다. 모델 설치 후 **이 모델 사용**으로 선택해야 번역 모델이 바뀐다.

TranslateGemma는 전용 프롬프트 구조를 요구하므로 현재의 2단계 JSON 다중 큐 방식에 최적화되지 않았다. 사용성 검증 없이 해당 모델을 자동 추천하지 않는다.

## 검증 범위

`tests/test_translation_two_stage.py`, `tests/test_lyrics_translation_prompt.py`, `tests/test_local_llm.py`에 전체 가사 입력, 계획 전달, 취소, 실패 안전 전환, 선택 재번역, 다중 배치, 추천 모델 다운로드 흐름을 추가했다.

실제 클라우드/로컬 모델의 번역 자연스러움, JSON 응답의 안정성, 8GB GPU에서의 VRAM/RAM 사용량과 Windows 다운로드 UX는 실기기 QA가 별도로 필요하다.

## 로컬 모델 목록 조회 성능 개선

기존 Ollama 모델 목록 조회는 `/api/tags` 한 번 이후 **모든 설치 모델의 `/api/show`를 순차적으로 최대 5초씩** 확인했다. 모델이 많거나 응답이 늦을 때 대기 시간이 모델 수에 비례하여 크게 증가하는 문제였다.

- 모델 인덱스는 `/api/tags`로 한 번 조회하고, 아직 검증하지 않은 모델만 **최대 4개 병렬** 상세 조회한다(개별 4초 제한).
- 모델 이름+다이제스트로 검증 결과를 캐시한다. 변하지 않은 모델은 새로고침에서 `/api/show`를 다시 호출하지 않는다.
- 서비스 설정창과 모델 관리자는 **동일한 LocalLLMService 객체**를 재사용하므로, 창을 오가면서 이미 검사한 모델을 재검사하지 않는다.
- 다이제스트가 바뀐 모델은 다시 검증하고, 검사 실패는 캐시하지 않아 다음 조회에서 복구할 수 있다.
- 설치형 생성 모델만 표시하도록 기존 completion capability, remote_host, LM Studio type 검사를 유지한다. 모델 목록과 로컬 서버 요청에서 가사 내용이나 계정 키를 캐시에 보존하지 않는다.
- 실제 시간 단축 효과는 설치 모델 수, 로컬 서버 버전 및 응답 속도에 따라 다르다. **실기기 시간 측정 전 고정 배속 개선을 주장하지 않는다.**

검증: `tests/test_local_llm.py`에 병렬 요청 수, 캐시 재사용, 다이제스트 변경, 일시적 검사 오류 복구, 서비스 재사용 회귀 테스트를 추가했다.

## 로컬 LLM `finish_reason=length` 자동 복구

Qwen3.5 9B 등 추론 지원 모델에서 빈 응답과 `finish_reason=length`가 자주 발생하던 원인을 완화한다.

- **Ollama:** OpenAI 호환 채팅 경로 대신 공식 네이티브 `/api/chat`을 사용한다. `think: false`로 비활성화 가능한 추론 모델이 번역문 전에 출력 예산을 소진하는 문제를 줄이고, `format: "json"`을 적용한다. 출력 예산은 기본 3,072토큰, 한 줄 재시도에서는 6,144토큰으로 늘린다. 문맥 창은 8,192토큰을 기본으로 하고 긴 요청/재시도에서 확대한다.
- **LM Studio:** 기존 OpenAI 호환 요청을 유지하며 `max_tokens`를 명시한다.
- 로컬 LLM 배치는 **최대 6큐/1,200자**로 변경한다. 모델이 출력 한도에 도달하거나 본문 없이 끝난 경우, 자동으로 반으로 나눠 재시도한다.
- **한 줄에서의 무한 재시도를 방지**한다. 한 번만 더 큰 출력 예산으로 재시도하고 그래도 실패하면 실제 오류로 처리한다.
- 여러 줄을 나눠 번역하던 도중 일부 줄만 실패하면 성공한 줄은 부분 결과로 보존하고 실패한 줄만 검토 대상으로 남긴다. 모든 요청 사이에 취소 여부를 확인한다.
- 작업 UI에 자동 재시도 상태를 표시하고, 로컬 모델이 추론만 생성하거나 빈 응답을 반환했을 때 원인 메시지를 구체화한다.
- 로컬 전체 가사 1단계 분석이 16,000자를 넘으면 문맥이 잘린 것을 완전 분석으로 오인하지 않도록 기존 문맥 번역으로 전환한다.

`tests/test_local_llm_generation_limits.py`에는 Ollama 네이티브 요청 규격, 자동 분할, 한 줄 예산 증가, 재시도 한도, 부분 성공 보존, LM Studio 호환성, 취소 회귀 테스트를 포함한다. 실제 Qwen3.5:9B/Windows/Ollama 조합에서 품질과 속도 측정은 별도 필요하다.

## 프롬프트 압축 및 중복 문맥 제거 (2026-11-19)

작은 로컬 LLM의 입력 토큰 낭비를 줄이도록 지침과 반복 제공 데이터를 압축했다.

- **1단계 분석 지침:** 약 2,704자 → **757자** (약 72% 감소).
- **2단계 번역 지침:** 약 10,487자 → **1,448자** (약 86% 감소).
- 1단계 분석이 성공하면, 2단계에서 **곡 전체 가사를 반복해 보내지 않는다**. `song_context.coverage="in_plan"`과 빈 `cues`만 보내고, 핵심 분석 요약 + 인접 가사 + 기존 번역을 참고한다.
- 1단계 분석이 실패하면 기존의 `whole_song_context`를 계속 사용하므로 **기존 번역 경로와 문맥 복구**는 유지한다.
- 전달할 분석 요약은 최대 3개 반복구절, 6개 용어와 짧은 문장으로 제한한다. 전체 곡 분석 자체는 원본 전체 가사(기존 길이 제한 내)를 유지한다.
- 로컬 LLM의 이전 번역 참고는 시작 문체 앵커 최대 2줄과 최근 최대 6줄, 총 **900자** 안에서 선택한다. 클라우드 모델은 최근 최대 8줄, **1,600자**를 참고한다.
- JSON 계약, 원문 영어 번역 누락 검사, 후렴 일관성, 이전 번역 참고, 취소·실패 복구, 구조 검사 방식은 삭제하지 않았다.

이 감소율은 **시스템 프롬프트 문자열 길이**의 비교이며, 전체 API 요청 토큰/실제 실행 시간의 정확한 감소율과는 다르다. 모델별 출력 품질과 실측 속도는 Windows/Ollama 실기기에서 확인해야 한다.
