# UI 응답성·사용 흐름 개선 — 2026-10-08

기존 작업 트리의 변경을 보존하고 음악 추가, 검색, 콘텐츠 재사용, 실행취소 경로를 개선했다. 새 의존성은 추가하지 않았다.

## 확인한 원인과 수정

| 경로 | 문제 | 적용한 수정 |
| --- | --- | --- |
| 음악 추가·드롭·M3U8 가져오기 | UI 스레드에서 Mutagen 읽기와 최대 15초의 FFprobe 대기 | 공통 음악 검사 경로를 QThread로 이동. 작은 커버도 QImage로 미리 준비한다. 실제 곡 추가는 GUI 스레드에서 한 번에 처리한다. |
| 음악 검사 취소 | 작업 상태·중단 방법이 없고 FFprobe가 끝날 때까지 기다림 | 지연 표시되는 진행 창, 현재 파일·개수, 취소 버튼. 취소한 검사 결과는 추가하지 않으며 FFprobe를 종료·회수한다. 기존 QThread 정리 함수를 재사용한다. |
| 곡 검색·추가 | 검색마다 곡 행과 커버 재생성, 추가할 때 기존 행까지 다시 생성 | 기존 행의 표시만 전환하고 새 곡만 붙인다. 변경된 행만 교체하고 일괄 갱신 중 재그리기를 억제한다. |
| 프로젝트 콘텐츠 | 변경 없는 갱신에도 모든 항목·아이콘 재생성, 다중 선택 손실 | 항목 재사용. 파일 수정 시각·크기·보기 방식이 바뀔 때 아이콘 갱신. 선택·현재 항목·스크롤 보존. |
| 자동 가사 연결 | 같은 폴더를 곡마다 다시 탐색 | 가져오기 배치 안에서 폴더별 한 번만 탐색. 독립 호출은 기존 방식 유지. |
| 실행취소 기록 | 변경 없는 상태도 JSON 왕복 복사 | 동일 상태를 먼저 비교해 불필요한 복사를 생략. 변경 상태의 복사·격리는 유지. |

## 사용자 흐름 시뮬레이션

300곡으로 다섯 검색어를 세 번씩 바꿔 총 15번 갱신했다. 음악 검사에는 재현 가능한 800ms 지연을 넣었고 10ms UI 타이머로 응답성을 관찰했다. 실제 파일 전체를 읽는 시간이나 전체 앱의 속도 배수가 아니라, 해당 갱신·검사 경로의 결과다.

| 측정 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 검색 갱신 중앙값 | 203.62ms | 1.69ms |
| 검색 갱신 최대 | 726.70ms | 8.64ms |
| 검색 중 생성한 곡 행 | 2,400 | 0 |
| 느린 음악 검사 중 UI 타이머 실행 | 0회 | 80회 |
| 검사 시작부터 곡 추가까지 최대 타이머 공백 | 1,699.63ms | 49.38ms |
| 음악 검사 실행 위치 | GUI 스레드 | 작업 스레드 |

원본: [수정 전](benchmarks/2026-10-08-workflow-before.json), [수정 후](benchmarks/2026-10-08-workflow-after.json). 수정 전 최초 실행은 임시 폴더 접근 경고가 있었고, 수정 후에는 작업 폴더 아래의 임시 폴더를 사용했다. 두 실행은 동일한 300개 가상 곡과 검색어·모사 지연을 사용하며, 서로 다른 임시 폴더와 실행 부하에 따른 차이가 포함될 수 있다.

사용 흐름에 적용한 개선:

- 검색을 지우거나 음악을 추가해도 기존 곡 행·선택을 유지한다. 검색에서 숨겨진 선택은 삭제·복제·Space·Enter 대상에서 제외한다.
- 첫 곡의 위로 이동, 마지막 곡의 아래로 이동을 비활성화해 실행해도 아무 일 없는 버튼을 줄인다.
- 검색 안내에 파일명을 포함하고, 검색·곡 목록·화살표 버튼에 접근성 이름을 제공한다.
- 콘텐츠 갱신과 순서 변경 때 다중 선택이 현재 항목 복원으로 지워지지 않게 한다.
- 1280×800 창과 누락 메타데이터 화면을 Qt 이미지로 확인했다. 실제 스크린리더 사용성이나 사용자 대상 평가를 수행한 것은 아니다.

## 검증과 재현

새 회귀 검사 10개: 느린 검사 중 heartbeat, GUI에서만 최종 추가, Escape 취소, 취소 결과 폐기, 오류 후 재시도, FFprobe 자식 종료·회수, 검색·추가 시 행 재사용, 숨긴 곡의 안전성, 다중 선택·버튼·접근성, 폴더당 가사 탐색, 실행취소 데이터 격리.

실제 설치된 FFmpeg로 영상 합성·취소와 미리보기 테스트 10개가 skip 없이 통과했다. CPU 미리보기의 30초 재생과 열기·일시정지·탐색·재개·닫기 반복을 포함한다. 정상·취소 가능한 FFprobe 경로 모두 실제 WAV 길이 1.500초를 반환했다.

전체 회귀 검사: **125/125 모듈 성공, 1,672개 검사, 실패·오류 0, 조건부 skip 69, 384초**. skip에는 선택 설치 모델, 실제 FFmpeg·장시간 재생 opt-in, offscreen OpenGL, Windows에서 사용할 수 없는 POSIX 기능이 포함된다. 실제 미디어 검사는 위처럼 별도 활성화해 확인했다. 마지막 진행률·선택 유지 변경 후 관련 **48개 검사도 skip 없이 통과**했다. `compileall`과 변경 파일의 `git diff --check`도 확인했다.

최초 테스트 시도는 샌드박스의 기본 임시 폴더 접근 오류 때문에 세 모듈이 timeout이었다. 이후 위 재현 명령처럼 작업 폴더 안으로 임시 경로를 옮겨 전체 검사를 완료했다. 테스트용 설정·캐시·복구 데이터는 격리했다.

```powershell
$env:TEMP = Join-Path (Get-Location) 'work\test-temp'
$env:TMP = $env:TEMP
$env:PYTHONIOENCODING = 'utf-8'
New-Item -ItemType Directory -Force -Path $env:TEMP | Out-Null
& .build-venv312/Scripts/python.exe tools/user_workflow_benchmark.py --output work/workflow.json
& .build-venv312/Scripts/python.exe scripts/run_tests.py --timeout 240 --report work/optimization-full-tests.json
```

남는 범위: 최초 대규모 목록의 Qt 위젯 생성, 네트워크 폴더 자체의 파일 접근 지연, Mutagen 읽기 중 즉시 중단, GPU/4K 장시간 재생은 이번 측정이 보장하지 않는다. 가사 파일 읽기는 여전히 GUI 경로지만 폴더의 반복 탐색을 줄였다. 수천 곡에서 최초 목록 생성이 문제로 측정되면 가상화 목록을 고려한다. 설치 프로그램·배포 실행 파일은 빌드하지 않았다.
