# 사용자 지정 애니메이션 편집기 완성도 개선

2026-11-03. 기존 곡 시작·곡 끝 모션의 독립 속성 곡선 모델과 전용 Canvas 복제 구조를 유지했다. 범용 키프레임 편집기를 복원하거나 프로젝트 데이터를 자동 변환하지 않았다.

## 1. 확인된 문제와 원인

- 시작 사용자 지정 모션은 마지막 자세를 유지하지만, 종료 사용자 지정 모션은 기본 요소 기준의 독립 자세로 시작한다. 두 자세가 달라도 기존 편집기에는 안내나 연결 도구가 없었다.
- `CanvasSnapshot`의 컴파일된 계획 경로는 시작 마지막 자세를 유지하지만, 계획 없는 캡처는 이 자세를 누락했다. 종료 프리셋과 조합하면 경로 간 위치·투명도가 달라질 수 있었다. 같은 유지 규칙으로 수정했다.
- 기존 편집기는 다섯 속성의 트랙·곡선 도구를 한 번에 노출했다. 공통 시간축과 고급 도구를 선택해서 볼 수 있도록 했다.
- 영상 복제본은 이미지로 바뀌어 프레임이 고정되었다. 음악 반응 분석도 편집기에 전달되지 않았다.
- Canvas의 수평 이동도 X/Y 값을 함께 전달해 바뀌지 않은 Y에 점을 만들 수 있었다. 실제 변경된 속성만 키를 만든다.
- 음악 반응으로 변형된 텍스트·배경의 편집 핸들에는 해당 변형이 반영되지 않았다. 기존 반응 자세 계산을 핸들에도 적용했다.
- Undo를 위해 숨겨 둔 요소도 복제되면 편집기에서 다시 나타날 수 있었다. 실제 보이는 요소만 복제한다.
- 연결·미디어·이전 데이터 안내가 동시에 있는 작은 창과 영어 150%에서는 하단이 화면을 벗어나거나 오른쪽 숫자 입력이 잘렸다. 빈 안내 공간을 접고, 작은 화면의 보기 도구를 메뉴로 모으며 속성 패널의 최소 너비를 보장했다.

## 2. 시작·끝 연결과 합성 정책

비교 대상은 평가된 X/Y 이동량, 크기, 회전, 투명도 배율이다. 꺼진 속성은 저장된 키 값 대신 실제 적용되는 기본 상대값을 사용한다. 허용 오차는 위치 0.1px, 회전 0.1도, 크기·투명도 배율 0.001이다. 회전은 360도의 정수배 차이를 같은 자세로 본다. 기본 위치·투명도나 다른 효과는 수정하지 않는다.

| 시작 | 종료 | 정책 |
| --- | --- | --- |
| 사용자 지정 | 사용자 지정 | 시작 마지막 자세를 유지하다가 독립 종료 자세로 전환. 실제 차이가 있으면 안내 |
| 사용자 지정 | 프리셋 | 유지한 자세에 프리셋의 이동·회전을 더하고 크기·투명도를 곱함 |
| 사용자 지정 | 없음 | 시작 마지막 자세 유지 |
| 프리셋 또는 없음 | 사용자 지정 | 기본 상대 자세와 종료 첫 자세 비교 |
| 프리셋 또는 없음 | 프리셋 또는 없음 | 기존 동작 유지 |

사용자가 **시작 애니메이션의 마지막 자세 가져오기**를 누를 때만 종료 첫 키의 다른 값을 맞춘다. 이후 키, 보간 방식, 베지어 핸들과 사용자 지정 구간 표시는 보존한다. 꺼진 종료 속성이 목표 자세와 다르면 그 속성을 켜야 실제 연결되므로 이 동작을 버튼 설명에 알린다. 연결 자체는 로컬 Undo 한 번으로 복원할 수 있다. 단순 조회·모드 전환·곡 시작/끝 전환은 저장 데이터를 바꾸지 않는다.

## 3. 간단·고급 모드

처음에는 **간단 모드**를 연다. 큰 Canvas, 현재 자세 값, 공통 시간축, 자세 추가·삭제·이전·다음, 재생, Undo/Redo와 적용·취소를 제공한다.

- 공통 시간축은 모든 속성 키 시각의 합집합이다. 다시 샘플링하거나 공통 곡선으로 변환하지 않는다.
- 수치·Canvas 편집은 바뀐 속성에만 키를 추가·수정한다.
- 명시적인 자세 추가는 해당 시점에 키가 없는 켜진 속성에 키를 만든다. 이미 있는 키의 보간은 건드리지 않는다.
- 삭제·이동은 해당 시점의 켜진 속성 키에만 적용한다. 꺼진 키는 보존하고 회색으로 표시한다. 끝점과 충돌하는 시각은 이동·삭제하지 않는다.
- 여러 속성의 공통 이동은 한 Undo로 처리한다.

**고급 모드**는 기존 다섯 트랙, 활성화, 구간별 보간·베지어·프리셋과 수치 조절을 유지한다. 전환은 위젯 표시만 바꾼다. 두 모드의 편집은 동일한 임시 모션과 Undo 스택을 사용한다.

## 4. 프로젝트 미리보기

프로젝트의 Source를 깊은 복사한 전용 Scene을 계속 사용한다. 배경·이미지·커버·텍스트·Now Playing·기타 레이어를 기존 `CanvasSnapshot`으로 캡처하고, 핸들은 별도 Scene에만 표시한다. 원본 SourceStore, 자동 저장과 프로젝트 History에 재생·탐색 이벤트를 전달하지 않는다.

메인 창에서 편집기를 열면 기존 `CompiledRenderPlan`을 전달한다. `motion_windows`와 `visual_segments`로 선택 곡의 미디어 시간을 정하고, 원본 곡 시간·재생 속도·믹스 화면 소유권을 재사용한다. 다른 요소는 실제 계획을 기준으로 평가한다. 선택 요소만 명시적인 임시 자세를 적용하여 효과 전체를 편집할 수 있게 한다. 효과 밖 종료 이전 구간은 시작 마지막 자세를 표시해 실제 경계 차이를 확인할 수 있다.

16ms 단발 렌더 요청 병합과 33ms 재생 타이머를 유지한다. Scene·SourceItem을 매 프레임 다시 만들지 않는다. 독립 곡선을 조회할 때 불필요하게 기본 곡선을 평가하던 경로와 한 자세에서 곡선 캐시를 여러 번 조회하던 경로도 줄였다.

## 5. 영상·음악 반응 지원 범위

영상은 복제본의 기존 `SourceItem`/`QMediaPlayer` 디코더와 `resolve_video_position`을 재사용한다. 파일 길이는 기존 비동기 probe 작업으로 구하고, 원본 디코더에서 이미 확인한 길이가 있으면 재사용한다. 이미 만들어진 미리보기 프록시가 있으면 재사용하며 편집기에서 새 프록시를 만들지 않는다. 곡별·전체 타임라인, 시작·중간 탐색, 종료 모션 시간, 속도, 한 번·반복·순서·무작위 규칙을 기존 스케줄러에 맡긴다. 명시적인 일시 정지 탐색은 작은 이동도 seek한다. 디코더 프레임 도착은 렌더 요청으로 병합한다.

**영상 동기화**를 끄면 마지막 정지 화면을 유지한다. 닫을 때 복제본의 플레이어·비디오 싱크를 해제하고, 진행 중인 probe는 중단 요청 후 응용 프로그램 소유로 옮겨 완료 시 정리한다. FFprobe를 기다리며 창 닫기를 막지 않는다. 원본 Canvas 디코더는 편집기가 소유하거나 해제하지 않는다.

일반 재생 미리보기에서 완료한 베이스·음악 반응 envelope를 두 곡까지 보관하는 공유 메모리 캐시에 전달한다. 파일 경로·크기·수정 시간으로 오래된 결과의 재사용을 막는다. 편집기는 저장된 실제 분석을 텍스트·가사·배경에 사용하며 오디오를 새로 디코딩하거나 분석하지 않는다. 데이터가 없는 효과는 예시값을 사용한다. 시각화·파형·레벨 미터·파티클은 예시 상태를 유지한다. 실제 분석·예시·혼합 상태를 화면에 구분해 표시한다.

## 6. 이전 프로젝트 호환

기존 전체 영상·특정 곡·곡별 키프레임 은행을 유지하며 편집기에 존재 범위를 안내한다. 활성 이전 데이터가 있으면 기존처럼 재생 중지와 데이터 보존을 확인해야 적용할 수 있다. 적용 시 `enabled`만 끄고 곡선 자체를 지우지 않는다. 이미 꺼진 이전 데이터는 불필요하게 다시 쓰지 않는다.

시간 모델이 달라 무손실 자동 변환은 제공하지 않는다. 별도 범용 편집기나 변환·내보내기 UI도 추가하지 않았다. 원본 프로젝트를 별도 파일로 저장하면 기존 데이터와 새 사용자 지정 모션을 함께 보존할 수 있다. 프로젝트 파일 저장·복원과 모션/이전 은행의 공존은 기존 회귀 테스트로 확인한다.

## 7. 렌더 검증

기존 CPU/GPU 어댑터, FFmpeg 상대 모션 수식, `CompiledRenderPlan`과 화면 소유권 계산을 유지한다. 연결된 두 모션의 경계를 실제 MP4로 인코딩·디코딩해 Canvas의 위치·알파와 비교하는 테스트를 추가했다. 기본 투명도 40%와 상대 투명도 70%의 조합도 포함한다. 기존 베지어 오버슈트·독립 속성 시각·영상 알파 중복·GPU 회전/알파·AutoMix 재계획·크로스페이드·짧은 곡 테스트를 유지한다.

선택 요소의 제작 시간과 실제 출력의 제한된 시간은 구별한다. 편집기는 설정한 지속 시간으로 효과 전체를 조작하며, 프로젝트 계획이 있으면 미디어 시간은 실제 출력 구간에 대응한다. 짧은 곡·노출 구간·믹스 맞춤에 따라 실제 영상에서 효과 길이가 달라질 수 있다.

최초 전체 실행의 클립보드·마우스 커서·타이머 관련 실패는 기본 offscreen 테스트 환경에서 재실행해 통과했다. 로컬 OAuth 모의 서버는 샌드박스의 소켓 권한 제한으로 시간 초과되어 허용된 환경에서 재실행했다. 도움말 주제 개수를 1개로 고정한 검사는 원본 도움말에서도 실패함을 재현한 뒤 실제 필터 결과 수를 검증하도록 보완했다. 제품 코드를 바꿔 관련 없는 실패를 감추거나 테스트를 비활성화하지 않았다.

남은 건너뜀은 선택 실행하는 실제 Beat This 모델 3개·Sonara 2개와 Windows에서 지원하지 않는 POSIX FIFO 6개다. 이번 편집기 때문에 새 모델을 내려받거나 선택 의존성을 설치하지 않았다. 그 외 FFmpeg 옵션 때문에 처음 건너뛴 테스트는 FFmpeg 경로를 지정해 다시 실행했다.

실제 NVIDIA RTX 5060/OpenGL에서 GPU 비교와 30초 재생, 반복 열기·이동·닫기를 포함한 기존 영상 안정성 모듈도 통과했다. 새 편집기 테스트는 실제 MP4의 프레임 갱신, 속도·루프·종료 시점과 해제, probe 중 즉시 닫기, 실제 분석/예시 구분, 의도된 자세 차이 유지, 연결 Undo와 공통 시간축 마우스 드래그를 포함한다. AutoMix·크로스페이드의 같은 시각에서 편집기와 Canvas를 비교할 때 8비트 알파 반올림 차이를 허용하되 최대 채널 오차 1 이내로 검사한다.

4K Canvas, 이미지 30개·텍스트 20개·시각화·영상·선택 도형 등 총 53개 요소와 200점 모션으로 실제 Qt 화면을 확인했다. 한국어 100%는 탐색+렌더 중앙값 **13.19ms**, 95백분위 **38.67ms**, 최대 **56.86ms**였다. 첫 열기는 한국어 769.87ms, 영어 150% 861.39ms로 초기 리소스 비용이 있었으며 후속 열기 측정은 JSON에 개별 기록한다. 이 수치를 모든 프로젝트의 응답 속도로 일반화하지 않는다.

한국어는 20회 열기·닫기 후 원본 데이터 동일성, 타이머 종료와 디코더·싱크 해제를 검사했다. 마지막 5회 RSS는 약 376~377MiB 범위로 안정적이었다. 짧은 반복 검사이며 장시간 모든 조합의 메모리 누수가 없다는 보장은 아니다. 영어 150%도 같은 구성으로 검사했으며 중앙값 16.05ms·95백분위 44.44ms였다.

1024×768 논리 화면을 모의한 작은 창에서도 양 모드의 숫자 입력 전체와 적용 버튼이 보이고, Canvas 뷰포트 높이가 200px 이상인지 검사했다. 작은 화면의 고급 트랙은 스크롤한다. 실제 화면은 `work/motion-quality-ko/`, `work/motion-quality-en/`의 `simple.png`, `advanced.png`, `simple-small.png`, `advanced-small.png`에 남겼다. 프로그램 도움말의 한국어·영어 편집기 이미지도 새 화면으로 갱신했다.

Python 3.14.10, Qt/PySide6 6.12.0, FFmpeg 9.0.2에서 실행했다. `compileall`과 `git diff --check`도 통과했다. 재현 예:

## 10. 남은 제한

- 영상은 비동기 디코더이므로 탐색 직후 한동안 직전 프레임이 보일 수 있다. 모든 파일·코덱·드라이버에서 프레임 단위 seek 정확성을 보장하지 않는다. 미지원 영상은 기존 정지 화면·자리 표시자를 유지하고 동기화를 끌 수 있다.
- 편집기에서 전체 음악을 재생하거나 분석하지 않는다. 공유 분석 캐시는 메모리의 최근 두 곡만 보관하며 앱 재시작 후 유지되지 않는다. 시각화·파티클은 계속 예시다.
- 선택 요소의 전체 효과를 제작하는 화면이므로 실제 노출이 끝난 뒤에도 자세를 편집할 수 있다. 영상 자체는 원래 노출·반복 규칙을 따른다.
- 매우 짧은 요소 노출 구간에서는 기존 노출·애니메이션 우선순위 때문에 모션 일부만 표시될 수 있다. 독립 편집 창을 직접 생성하여 프로젝트 계획을 넘기지 않는 호출은 선택 곡의 순차 시간으로 미디어를 표시한다.
- 이 검증 PC의 Windows/Qt/FFmpeg/GPU와 샘플 프로젝트를 확인한다. 다른 OS·모든 GPU·코덱·대규모 실사용 프로젝트의 성능을 일반화하지 않는다.
