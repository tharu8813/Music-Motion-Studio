# 곡 시작·곡 끝 사용자 지정 애니메이션 편집기

> 후속 [편집기 완성도 개선](2026-11-03-motion-editor-completion.md)에서 선택적 자세 연결, 간단/고급 모드와 영상 동기화를 추가했다. 아래 미리보기 제한과 연결 설명은 1차 구현 당시 기록이다.

> 현재 이전 범용 키프레임 편집 화면과 속성별 편집 연결은 제거되었다. 아래 편집 UI 설명은 구현 당시 기록이다. 기존 프로젝트의 키프레임 데이터와 재생·저장 호환성은 유지하며, 새 모션은 곡 시작·곡 끝 편집기로 만든다.

> 이 문서는 1차 구현 기록이다. 현재 하단 UI는 [속성별 트랙·구간 곡선·효과 전후 재생](2026-11-03-motion-property-lanes.md)으로 개선되었다.

2026-11-03 구현 및 검증 기록. 기존 범용 키프레임 확장 작업에서 곡 시작·곡 끝 모션을 직접 만드는 방향으로 전환했다. 기존 감사에서 수정한 데이터 보호와 출력 오류 수정은 보존했다. 릴리즈 게시나 버전 변경은 수행하지 않았다.

## 1. 기본 화면에서 바꾼 기능

새 프로젝트의 속성창에서 속성별 키프레임 다이아몬드와 범용 키프레임 설정을 숨겼다. 하단 타임라인은 기존 시각·수치 타임라인을 기본으로 제공한다. 전체 영상·특정 곡·곡별 저장 방식을 새 모션 제작 과정에 노출하지 않는다.

속성창의 `곡 시작 애니메이션`, `곡 끝 애니메이션` 목록에 `키프레임으로 만들기...`를 추가했다. 선택한 쪽에만 `키프레임 편집...` 버튼을 표시한다. 새 편집기는 한 줄의 자세 키프레임 타임라인을 사용한다.

## 2. 보존한 기능과 오류 수정

기존 등장·퇴장 프리셋, 반복 모션, 음악 반응, 요소의 기본 위치·크기·회전·투명도, 기존 타임라인과 프로젝트 저장을 유지한다. 프리셋 목록과 사용자 지정 선택지를 구분해 기존 프리셋의 동작 계약도 유지했다.

이전 감사에서 완료한 다음 수정도 남겼다.

- 잘못된 점·지원하지 않는 속성·시간 충돌을 변경 전에 검사하고, 실패한 편집에서 기존 데이터를 지우지 않는다.
- 잠긴 요소의 중첩 속성 변경을 막고, 편집 대상 곡의 값과 시간 범위를 기준으로 평가한다.
- 범위를 벗어난 기존 점을 보존하고, 이전 편집기의 그룹 이동·취소·선택 복원을 보완한다.
- Canvas 키프레임 투명도, 영상 기본 투명도의 중복 적용, 비주얼라이저의 투명도 처리를 수정한다.
- 긴 FFmpeg 수식의 중첩 깊이와 큰 시간값의 정밀도를 개선하고 FFmpeg 9의 필터 파일 인자도 지원한다.
- 잘린 무음 구간에서 특정 곡의 키프레임이 적용되지 않도록 한다.

새 모션 검증에서 확인한 GPU의 회전 방향·알파 합성 차이도 수정했다. 회전은 픽셀 좌표에서 계산하고, 사용자 셰이더의 VAO를 분리했다. PySide의 스칼라 uniform 오버로드 문제는 명시적인 GL 스칼라 호출로 처리했다.

## 3. 곡 시작 애니메이션

`요소 선택 → 애니메이션 → 곡 시작 → 키프레임으로 만들기... → 키프레임 편집...`으로 연다. 원하는 시간으로 이동한 뒤 화면에서 요소를 움직이거나 오른쪽 값을 입력한다. 현재 시간에 점이 없으면 보간된 자세를 바탕으로 점을 만들고 안내한다.

위치 X/Y와 회전은 기본값에 더하고 크기와 투명도는 기본값에 곱한다. 기본 X가 400이고 이동량이 +100이면 화면의 X는 500이다. 나중에 기본 X를 600으로 바꾸면 같은 자세는 700에 표시된다. 시작 모션의 마지막 자세는 종료 모션이 시작될 때까지 유지된다.

## 4. 곡 끝 애니메이션

`곡 끝`에서도 같은 흐름으로 별도 데이터를 편집한다. 편집 창 상단에서 시작·끝을 전환할 수 있다. 시작과 끝의 점·보간·지속 시간은 독립적이며, 단순히 반대쪽으로 전환해 보는 것만으로 그쪽 모션을 활성화하지 않는다.

끝 모션은 기본 요소를 기준으로 독립적인 자세를 사용한다. 시작 마지막 자세와 끝 첫 자세가 다르면 경계에서 차이가 생길 수 있으므로 두 자세를 맞춰 제작한다. 기본 끝 모션은 불투명한 원래 자세에서 투명해지는 동작이다.

## 5. 독립 편집 창과 프로젝트 Canvas

상단에 대상 요소·시작/끝·지속 시간, 중앙 왼쪽에 큰 프로젝트 Canvas, 오른쪽에 위치·크기·회전·투명도·보간을 배치했다. 아래에는 자세 타임라인과 재생 도구, 맨 아래에는 취소·적용을 제공한다.

기존 `CanvasScene`, `SourceItem`, `CanvasSnapshot` 렌더링을 재사용한다. 프로젝트 배경과 다른 요소를 복제한 전용 Scene에 표시한다. 원래 GraphicsItem을 이동하거나 소유권을 바꾸지 않는다. 선택 테두리·크기 핸들·회전 핸들은 화면 위의 별도 편집 레이어에만 그려 최종 영상에 들어가지 않는다.

예시 곡을 바꾸면 실제 앨범 커버와 Now Playing 제목·아티스트가 바뀐다. 키프레임 데이터는 그대로이며 곡마다 별도로 저장하지 않는다. 곡이 없는 프로젝트에는 예시 콘텐츠를 제공한다.

## 6. 편집 UX와 반응성

- Canvas 드래그로 상대 위치, 핸들로 균일 크기와 회전을 편집하고 오른쪽 필드와 동기화한다.
- 한 번의 드래그를 편집 창 내부 Undo 한 번으로 되돌린다. 프로젝트 Undo와 분리한다.
- 재생·일시 정지·처음·반복·스크럽·현재/전체 시간·이전/다음 점·추가/삭제를 제공한다. 키프레임을 누르면 해당 시간으로 이동한다.
- 선형·유지·이징과 기존 베지어 편집기를 재사용한다. 베지어 적용·취소와 로컬 Undo를 검증했다.
- 원본/결과 비교, 중앙선·안전 영역 가이드, 맞춤·100%·확대/축소를 제공한다.
- 지속 시간은 0.1~10초다. 점은 0~1의 정규화된 시간으로 저장하므로 지속 시간을 바꿔도 상대 간격을 유지한다.
- 33ms 재생 타이머와 16ms 단발 렌더 요청 병합을 사용한다. 직접 조작 중 재생을 잠깐 멈추고 종료 후 이어간다. 평가 값은 프레임 누적 상태에 의존하지 않는다.
- 이미지 캐시는 기존 SourceItem을 사용한다. 영상 복제본은 디코더를 새로 열지 않는다. 닫을 때 타이머를 정지하고 전용 Scene 자원을 해제한다.

Windows 네이티브 Qt에서 한국어 100%, 영어 150% 화면을 확인했다. 최소 창 크기에서도 Canvas와 적용 버튼에 접근하는 테스트를 통과했다.

텍스트 요소 12개, 1920×1080 프로젝트, 선택 모션 100점, 825×466 미리보기 뷰포트에서 120회 탐색·렌더를 측정했다. 현재 PC에서 창 열기 280.29ms, 렌더 중앙값 2.77ms, 95백분위 3.14ms, 최대 3.66ms였다. 취소 후 모든 원본 Source 직렬화 값이 같았다. 이 수치는 해당 샘플의 측정이며 무거운 프로젝트 전체에 대한 성능 보장은 아니다.

## 7. 저장 및 이전 데이터 호환성

Source에 `custom_intro_keyframes`, `custom_outro_keyframes`를 추가했다. 각 점은 정규화된 시간, 상대 이동량, 크기 배율, 회전 오프셋, 투명도 배율, 보간과 베지어 제어점을 저장한다. 값이 없는 필드는 이전 프로젝트에 강제로 추가하지 않는다. 새 필드의 손상된 값만 정규화하고 기존 키프레임 은행은 변환하거나 삭제하지 않는다.

구현 당시에는 기존 전체 영상·특정 곡·곡별 곡선이 있으면 `이전 키프레임 (호환)` 화면을 제공했으나, 현재는 이 편집 화면을 제거하고 저장·재생 호환성만 유지한다. 사용자 지정 모션이 있는 요소에는 이전 곡선을 중복 적용하지 않는다. 활성화된 이전 데이터가 있으면 편집 창에서 이전 재생을 중지하되 데이터를 보존한다는 확인을 받아야 적용할 수 있다. 이전 데이터의 자동 변환은 하지 않는다.

편집 중에는 전용 복제본과 임시 모션만 변경한다. 취소·닫기에는 SourceStore 변경이나 자동 저장을 발생시키지 않는다. 적용 시 선택한 요소의 모션 데이터를 한 번 갱신하고 프로젝트 Undo 한 번으로 복원한다. 잠긴 요소는 변경하지 않는다. 프로젝트 파일 저장·로드 후 모션 데이터 보존과 이전 공용 지속 시간 필드가 새 지속 시간을 덮어쓰지 않는 것도 검증했다.

## 8. 미리보기와 실제 FFmpeg 출력

동일한 상대 모션 평가를 Canvas, 내보내기 캡처, CPU/GPU 동적 레이어, FFmpeg 수식에 연결했다. 기본 투명도는 한 번만 적용한다. 영상과 비주얼라이저의 원본 레이어는 사용자 지정 모션 적용 전에 프리셋 페이드를 중복 처리하지 않는다. 크기 변화와 베지어 오버슈트의 최대 범위를 내보내기 레이어 크기 계산에 포함한다.

| 대상 | 실제 검증 |
| --- | --- |
| 도형 | 이동·크기·회전·투명도를 실제 MP4로 출력해 Canvas와 위치·알파 비교 |
| 텍스트·이미지·앨범 커버 | 편집기와 출력 캡처의 프레임 일치, 프로젝트 파일 왕복 저장, 최종 MP4 10프레임 비교 |
| 영상 | 실제 FFmpeg 영상 레이어 그래프로 MP4 출력, 상대 위치와 투명도 중복 여부 비교 |
| 오디오 비주얼라이저 | 실제 FFmpeg 합성과 CPU 어댑터 비교, 네이티브 OpenGL과 CPU를 5개 시각에서 비교 |

텍스트·이미지·커버 출력 테스트는 Qt 원본과의 평균 채널 오차를 1 미만으로 검사한다. Windows 글꼴의 색상 안티앨리어싱은 MP4의 YUV420 변환으로 달라지므로, 별도로 동일한 색상 변환을 거친 기준 프레임과 평균 오차 1 미만·99백분위 오차 3 미만도 검사한다. 색상 변환 손실을 모션 오차로 판단하거나 모든 픽셀이 동일하다고 주장하지 않는다.

실제 GPU 비교에서 발견한 회전·알파 오류를 수정한 뒤 관련 네이티브 테스트 66개를 통과했다. 실제 미디어 GPU 재생 30초와 10회 열기·이동·닫기를 포함한 기존 안정성 모듈도 5개 모두 통과했다. 안정성 샘플은 기존 범용 키프레임 데이터이며, 새 모션의 GPU 정확도는 별도 비교 테스트로 검증했다.

## 9. AutoMix와 크로스페이드

`CompiledRenderPlan`과 기존 `visual_segments`의 화면 소유권을 기준으로 효과 시간을 계산한다. 믹스 중간의 화면 전환과 `믹스에 맞춤` 구간을 공유하며, 짧은 곡의 시작·끝 시간 제한과 재생 속도도 같은 기준을 사용한다. 요소 자체의 노출 구간도 반영한다.

새 테스트에서 크로스페이드의 화면 소유권·믹스 맞춤, AutoMix의 템포 변경 계획과 수동 전환 적용 후 재계획을 확인했다. 각 계획의 시작·끝 중간 시각에서 Canvas와 동적 출력 바인딩의 알파를 비교했다. 기존 AutoMix 계획·수동 전환 회귀 테스트도 통과했다. 모든 AutoMix 조합을 실제 장시간 영상으로 출력한 검증은 아니다.

## 10. 테스트 결과와 재현

전체 183개 모듈 실행과 수정 후 대상별 재실행을 합쳐 **2,354개 중 2,343개 통과, 11개 건너뜀, 남은 실패 0개**다. 같은 테스트를 반복 실행한 횟수는 합산하지 않았다. 모듈별로 가장 많은 테스트와 가장 적은 건너뜀을 가진 통과 결과를 선택한 상세 근거는 [검증 JSON](benchmarks/2026-11-03-custom-motion-editor.json)에 있다. 건너뛴 항목은 실제 AI 모델 선택 실행 5개와 Windows에서 지원하지 않는 POSIX FIFO 테스트 6개다.

최초 전체 실행은 2,346개, 182/183 모듈 통과였다. 사용자 지정 항목을 고정 프리셋 목록에 넣어 생긴 `test_motion_curves` 실패를 프리셋과 선택지의 분리로 수정했다. 이후 새 네이티브 테스트에서 발견한 GPU·색상 비교 문제도 수정하고 다시 확인했다. 따라서 위 합계는 한 번의 무결점 전체 실행이라는 의미가 아니다.

마지막 키프레임·출력 회귀 실행은 122개 중 120개 통과·2개 건너뜀, 네이티브 새 편집기·모델·AutoMix·프리셋 실행은 102개 모두 통과, 영어 150% GUI는 13개 모두 통과했다. 별도로 이전 추가 속성 키프레임의 실제 GPU 비교를 포함한 13개도 모두 통과했다. `compileall`과 `git diff --check`도 통과했다.

## 12. 남은 제한

- 편집 창의 영상은 원본 Canvas의 현재 프레임 또는 정지 화면이다. 별도 영상·오디오 재생을 시작하지 않으며, 음악 반응·파티클은 예시 상태다. 창 안에서도 이 제한을 안내한다. 모션의 시간·자세 계산은 유지한다.
- 크기 핸들은 비율을 유지하는 크기 배율을 편집한다. 너비·높이를 개별로 키프레임화하는 범용 편집기는 아니다. 격자·스냅은 새 창에 추가하지 않았다.
- 시작 마지막 자세와 끝 첫 자세를 자동 연결하지 않는다. 독립 편집한 두 자세를 사용자가 맞춘다.
- 영상 요소의 기존 출력 제한 중 `없음`·`페이드`·`사용자 지정` 외의 등장·퇴장 프리셋과 반복 모션 제한은 유지한다. 지원하지 않는 설정은 오류로 알린다.
- 편집기에서는 효과 전체를 제작할 수 있도록 선택 요소의 노출 제한을 임시 복제본에서 해제한다. 실제 짧은 곡이나 요소 노출 구간에서는 기존 출력 시간 제한과 믹스 맞춤에 따라 효과 길이가 달라질 수 있다.
- 현재 PC의 네이티브 GUI·GPU·실제 FFmpeg로 검증했으며, 모든 해상도·글꼴·코덱·영상 파일·GPU 드라이버 조합까지 확인한 것은 아니다.
