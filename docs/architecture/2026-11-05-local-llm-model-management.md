# 로컬 LLM 모델 관리 흐름 개선

참고 구현: [Namu의 로컬 모델 관리](https://github.com/tharu8813/namu) (`src/app.js`의 모델 온보딩, 다운로드, 선택 및 삭제 흐름). UI 디자인이나 코드 자체를 이식하지 않고 **사용자 작업 순서**를 PySide6 기반 Music Motion Studio에 맞게 적용한다.

## 처음 사용하는 경우

1. **로컬 AI 연결 확인:** 관리자 진입 시 Ollama/LM Studio에 연결하고 설치된 모델을 조회한다. 이미 실행 중인 Ollama를 재사용한다. 연결이 실패하면 연결 오류와 실행 환경 준비 버튼/안내를 제공한다. 실행 환경 자동 설치는 기존과 같이 **기본 주소의 Windows x64 Ollama**에만 해당한다. LM Studio 설치는 별도 앱에서 진행한다.
2. **모델 준비:** 설치된 모델이 없다면 바로 모델 찾기 탭으로 이동한다. 카탈로그에서 언어/코딩 용도·크기·설명을 검색해 다운로드한다. 이미 설치된 모델은 카탈로그에서 이를 표시하고 중복 다운로드 대신 바로 사용할 수 있다. 기타 모델명 입력은 고급 옵션으로 남긴다.
3. **설치 진행 확인:** 다운로드가 시작되면 버튼과 탭을 비활성화하고, 취소 버튼과 진행률·서버 상태·파일 전송량·가늠 가능한 속도 및 남은 시간을 표시한다. 모델 ID 오류, 디스크 부족을 구별해 안내하고 같은 모델을 다시 시도할 수 있다. 실제 속도는 관측된 구간에 의한 추정이며 반드시 표시되는 것은 아니다.
4. **사용할 모델 선택:** 다운로드 완료 후 설치 목록으로 돌아와 새 모델을 선택한다. 사용자가 **이 모델 사용** 버튼을 눌러야 번역 서비스 설정에 적용된다. 설치 목록에서 다른 모델을 고르거나 행을 두 번 클릭해 전환할 수도 있다.

## 삭제 및 안전성

- 일반 사용자의 설치 목록에서 모델 삭제에 접근할 수 있도록 이동하되, 삭제 전 **해당 모델이 같은 Ollama 서버를 쓰는 다른 앱에서도 사라진다**고 확인한다.
- 모델을 삭제했거나 기존 설정의 모델이 서버에서 보이지 않는 경우, 다른 모델로 조용히 갈아타지 않는다. 사용자가 설치된 모델을 명시적으로 선택해야 한다.
- LM Studio는 공식 REST API가 제공하는 다운로드·조회·메모리 관리를 사용하고, **파일 삭제는 LM Studio 앱 자체에서** 처리하도록 유지한다. 지원되지 않는 삭제 API를 가정하지 않는다.
- 개발자용 메모리 로드/해제·별칭·원본 메타데이터는 고급 관리 탭에 둔다.

## Namu와 의도적으로 다른 점

Namu는 Ollama 기반 로컬 채팅 앱이며 설치본에 Ollama CPU 실행 파일을 포함할 수 있다. Music Motion Studio는 가사 번역 프로그램으로 Ollama·LM Studio **두 실행 환경을 지원**한다. 또한 최초 번역 언어 선택, 번역 JSON 형식 검증, 이미 번역된 가사 보존 등이 있으므로 모델 선택을 기존 번역 서비스 설정과 연동하되 **사용자가 선택한 경우에만 반영**한다.

확인할 테스트: 초기 모델 목록, 저장된 모델의 복원/누락, 카탈로그 중복 다운로드 방지, 다운로드 상태 및 취소, 삭제 동의와 설치 목록 갱신, 모델이 사라진 경우의 자동 대체 방지.
