# 작업 공간 사용성 개선 — 2026-10-29

2026-10-28 점검에서 발견한 문제를 기존 PySide6 UI 안에서 개선했다. 기존 작업 트리에 있던 가사·TTML 변경은 보존했다.

## 변경된 동작

- **캔버스 맞춤 유지:** 전체 맞춤을 선택한 후 창이나 패널 크기가 바뀌면 캔버스를 다시 맞춘다. 사용자가 확대 버튼·Ctrl+휠·배율 복원으로 직접 배율을 지정하면 이후 크기 변경에도 그 배율을 유지한다. 맞춤 중 스크롤바의 표시 변화가 다시 크기 변경을 일으키는 루프를 방지한다.
- **작은 화면:** 메인 창의 초기 크기에 화면의 작업 가능 영역을 반영하고 최소 크기를 낮췄다. 새 프로젝트·내보내기는 본문만 스크롤하며 실행·취소 버튼은 하단에 고정한다. 대화상자의 크기와 위치는 표시되는 화면 안으로 제한한다. 처음 실행할 때 하단 패널 높이는 기존 기본 상수를 사용하며 사용자가 저장한 패널 크기는 유지한다. 작은 창에서는 상단 작업 공간에 최소 높이를 확보하고 하단 패널이 줄어들 수 있게 했다.
- **쉬운 내보내기:** 권장·빠른·고화질 등 일반 프로필은 고급 설정을 접은 상태로 시작한다. 저장된 사용자 설정이나 `사용자 설정`을 선택하면 고급 항목을 보여 준다. 펼치기 체크박스에 이름을 붙였으며 펼치거나 접어도 값은 유지된다. 오디오·자막 전용 출력의 항목 표시도 유지한다. 최종 실행 버튼은 강조색으로 표시한다.
- **속성 탐색:** 탭이 들어갈 공간이 부족하면 모든 사용 가능한 범주를 드롭다운으로 표시한다. 충분히 넓으면 기존 탭을 사용한다. 선택 요소 제목과 탐색부는 고정하고 각 범주의 내용만 스크롤한다.
- **접근성:** 속성 입력란 및 새 프로젝트·내보내기 폼에 라벨 연결과 컨트롤별 접근성 이름을 지정한다. 기존 상세 설명은 유지한다. 언어 변경 시 이름도 갱신한다.
- **가사 상태와 출력 문구 분리:** 속성에 가사 미등록 곡 수, 실제 출력 문구에 대한 안내, 가사 검색·연결 진입점을 제공한다. 새로 추가한 가사 요소와 디자인 프리셋은 가사가 없을 때 영문 안내문을 영상에 자동 삽입하지 않는다. 텍스트 범주에서 출력 문구를 직접 편집하고 비울 수 있다. 기존 프로젝트의 `text`와 `subtitle_fallback`은 열기·선택·포커스 이동으로 변경하지 않는다. 사용자가 문구를 바꿀 때에만 두 값을 함께 갱신한다.
- **가독성과 명칭:** 공통 설명 글자를 11px에서 12px로 키웠다. 메뉴·도움말의 `가사/자막 편집기` 명칭에 맞게 기존 테스트 기대값을 갱신했다.

## 검증 방법

`tests/test_responsive_workspace.py`에 다음 회귀 검사를 추가했다.

1. 맞춤 상태에서 창 크기를 연속으로 변경해도 전체 아트보드가 뷰포트 안에 남으며, 수동 배율은 보존되는지 확인한다.
2. 작은 화면과 낮은 창 높이에서 대화상자의 본문 스크롤 여부, 하단 버튼 접근 가능 여부를 확인한다.
3. 내보내기 고급 설정을 접고 펼쳐도 사용자 값이 유지되며 영상·오디오·자막 간 표시가 올바른지 확인한다.
4. 좁은 속성 패널에서 모든 범주에 접근할 수 있고 내용 스크롤이 제목을 움직이지 않는지 확인한다.
5. 접근성 이름이 항목별로 구분되며 한국어·영어 변경을 따르는지 확인한다.
6. 새 가사 요소에 안내 문구가 출력되지 않으며, 기존 프로젝트 문구는 실제 편집 전까지 보존되고 명시적으로 지울 수 있는지 확인한다.

최종 검증은 **152개 모듈 모두 통과**다. 테스트 **1,984개 중 1,911개 성공, 73개 건너뜀**이다. 소스 컴파일과 공백 검사도 통과했다. 마지막 패널 최소 높이 조정 후에는 맞춤·속성 탐색·대화상자·가사 문구 보존·패널 전환 등을 포함한 8개 검사를 추가 실행해 통과했다.

초회 전체 실행에서는 테스트 명칭을 수정하는 과정의 들여쓰기 오류로 `test_main_window` 모듈을 불러오지 못했다. 이를 수정하고 소스를 컴파일한 뒤 해당 모듈의 86개 검사를 모두 다시 실행해 통과했다. 최종 집계에는 이 재실행 결과를 사용했으며 초회 로그도 보존했다.

## 남은 확인 범위

실제 Windows 다중 모니터 간 이동·DPI 전환, 시스템 스크린리더, 실제 GPU 및 장시간 4K 내보내기는 별도 검증이 필요하다. UI 글자 크기 사용자 설정이나 자동 패널 접기는 추가하지 않았다. 이번 변경은 화면 크기에 따른 맞춤·탐색·스크롤과 필수 안내의 개선에 집중했다.

## 후속 수정: 미리보기 재생바 잘림

사용자가 제보한 재생바 잘림을 실제 미리보기 탭에서 재현했다. 하단 패널에 210px을 배정한 상태에서 탭을 제외한 컨트롤 공간은 176px이었고, 컨트롤들이 요구하는 높이는 그보다 컸다. 타임라인 영역이 50px으로 눌리면서 그 안의 46px 재생바와 헤더가 함께 들어가지 못했다. 버튼 영역에도 내용 최소 높이보다 낮은 56px 상한이 있었다.

미리보기의 정보·타임라인·버튼 영역은 실제 내용 크기를 사용하도록 바꾸고 고정 높이 상한을 없앴다. 하단 패널은 컨트롤 최소 높이와 탭 높이를 합산해 확보하므로 경계를 위아래로 끌어도 재생바가 가려지지 않는다. 작은 창의 미리보기에서는 영상 영역을 더 줄일 수 있도록 하고, 종료 시 편집기의 기존 최소 높이와 패널 설정을 복원한다.

1560×920, 1366×720, 1100×680, 960×520에서 재생바와 모든 버튼이 상위 위젯 안에 들어가는지 확인하는 회귀 검사를 추가했다. 패널을 최소로 줄인 뒤 탐색 바 클릭이 동작하고 편집기 높이 설정이 복원되는지도 검사한다.

## 후속 수정: 플레이리스트 곡 행이 보이지 않음

실행 중인 앱에서 `8곡 중 8곡 사용`과 목록 항목은 존재하지만 행 내용이 그려지지 않는 상태를 확인했다. 곡이 삭제된 상태는 아니었다.

실행 취소·다시 실행은 상태 복원 동안 메인 창의 화면 갱신을 멈춘다. 이때 플레이리스트 새로고침이 부모에게서 상속한 `updatesEnabled() == False`를 목록 자체의 명시적인 중지 상태로 저장했다. 그 결과 메인 창의 갱신을 재개해도 목록은 계속 그려지지 않았다. 같은 경로를 격리된 앱에서 재현했다.

목록이 원래 갱신 가능한 경우에만 새로고침 동안 갱신을 잠시 멈추고 다시 켜도록 변경했다. 부모가 이미 갱신을 멈춘 상태라면 자식의 명시적 상태를 건드리지 않는다. 외부 코드가 목록을 의도적으로 중지한 경우도 그대로 보존한다.

프로젝트 상태 복원 후 목록·뷰포트·곡 행의 갱신이 모두 활성화되고 8곡이 표시되는 회귀 검사와, 의도적인 갱신 중지 상태가 유지되는 검사를 추가했다. 관련 결과는 [플레이리스트 테스트](../../work/preview-controls-2026-10-29/playlist-tests.json)에 보관한다. 이미 실행 중인 Python 프로세스에는 수정된 소스가 자동 재로딩되지 않으므로 재실행 후 반영된다.
