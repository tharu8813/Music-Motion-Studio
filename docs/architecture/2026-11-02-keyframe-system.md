# 키프레임 시스템과 속성창 개편

> 현재 이전 범용 키프레임 편집 화면과 속성별 편집 연결은 제거되었다. 아래 편집 UI 설명은 구현 당시 기록이다. 기존 프로젝트의 키프레임 데이터와 재생·저장 호환성은 유지하며, 새 모션은 곡 시작·곡 끝 편집기로 만든다.

> 키프레임의 현재 기본 흐름은 [곡 시작·곡 끝 사용자 지정 편집기](2026-11-03-custom-motion-editor.md)를 따른다. 아래 범용 키프레임 구조는 이전 저장 데이터의 호환을 위해 유지한다.

## 1. 속성창 구성

기존 소스별 편집기와 SourceRegistry를 유지하면서 속성창 목적지를 다섯 개로 통합했다.

| 목적지 | 주요 설정 |
| --- | --- |
| 콘텐츠 | 텍스트·파일·글꼴·가사·곡 목록 등 소스별 설정 |
| 배치 및 변형 | 위치 X/Y, 너비/높이, 회전, 크기, 투명도 |
| 디자인 | 모양, 색상, 테두리, 그림자, 마스크, 필터 |
| 애니메이션 | 키프레임 활성화·시간 기준·대상 곡, 기존 등장/퇴장·반복·음악 반응 |
| 고급 | 레이어, 표시, 잠금 |

좁은 속성창에서는 기존의 카테고리 선택 상자를 사용한다. 긴 폼은 카테고리 안에서만 스크롤한다. 복잡한 키프레임 조작은 하단 타임라인의 `키프레임 편집` 보기에서 수행한다. `키프레임 편집기 열기`로 바로 이동할 수 있다.

레이아웃 목적지 정의는 `app/inspector/navigation.py`, 공통 속성 접근과 다중 선택 쓰기는 `selection_binding.py`, 키프레임 상태와 버튼은 `keyframe_binding.py`가 담당한다. 기존 유형별 편집기는 계속 각 SourceType의 표시 조건을 소유한다.

## 2. 데이터 모델과 평가 엔진

`Source.keyframes`에 다음 데이터를 저장한다.

```text
enabled
mode: global | single_track | per_track
target_track_id
global_curves[property] = [Keyframe(time, value, interpolation, bezier), ...]
single_track_curves[track_id][property] = [...]
per_track_curves[track_id][property] = [...]
```

시간 단위는 FPS에 종속되지 않는 초다. 키프레임을 저장할 때 마이크로초 단위로 정규화한다. 기본 보간은 Ease In Out이며 Hold, Linear, Ease In, Ease Out, 사용자 Bezier도 지원한다. 한 키프레임의 보간 설정은 그 키프레임에서 다음 키프레임까지의 구간에 적용된다. 첫 점 이전과 마지막 점 이후에는 각각 끝점 값을 유지한다.

공통 지원 속성은 위치 X/Y, 크기, 회전, 투명도다. 후속 확장으로 Canvas 소스의 너비/높이·블러·글자 크기·모서리 반경·테두리 두께·그림자 네 속성과 사용자 베지어 그래프를 추가했다. `PROPERTIES` 레지스트리가 이름·범위·지원 유형을 정의한다. 자세한 지원 범위와 실제 GPU 검증은 [고급 키프레임 검증 문서](2026-11-03-advanced-keyframes.md)에 기록한다. 색상 키프레임은 지원하지 않는다.

저장 데이터를 읽을 때 잘못된 시간, 무한대, NaN, 불리언 숫자와 알 수 없는 속성을 걸러낸다. 범위를 벗어난 속성값은 제한하며 같은 시각의 점은 마지막 값을 남긴다. 정렬된 점을 이진 탐색하므로 임의 시각으로 이동해도 이전 프레임에 의존하지 않는다.

## 3. 전체 영상

영상의 절대 시간을 그대로 평가한다. 곡 순서, 곡별 시작 시간, 믹스 길이가 바뀌어도 저장된 점의 시각은 변경하지 않는다. 음악이 없는 공백에서도 전역 애니메이션이 계속되도록 출력 샘플을 생성한다.

## 4. 특정 곡

`target_track_id`가 지정한 곡에만 해당 곡의 로컬 시간으로 적용한다. 대상을 바꾸어도 이전 대상의 점을 별도 뱅크에 보존한다. 다른 곡이나 공백에서는 기본 속성값을 사용한다.

곡이 비활성화되거나 삭제되면 대상 ID를 자동 교체하지 않는다. 속성창은 사용할 수 없는 곡을 표시하며 해당 타임라인 편집을 비활성화한다. Undo 또는 프로젝트 복원으로 같은 ID가 돌아오면 기존 데이터가 다시 연결된다.

## 5. 모든 곡 개별

곡 ID마다 다른 속성과 서로 다른 개수의 점을 저장한다. 각 곡은 로컬 00:00 기준이며 새 곡에는 애니메이션을 자동 복제하지 않는다. 곡 목록의 `◆`는 해당 곡에 점이 있다는 뜻이다. 이전/다음 곡 버튼, 직접 선택, 복사/붙여넣기, 현재 뱅크 초기화를 제공한다.

같은 음악 파일이나 같은 제목이어도 ID가 다르면 다른 곡이다. 순서를 바꾸어도 점은 원래 곡을 따른다. 삭제된 곡의 데이터는 프로젝트에 보존해 복원할 수 있게 한다. 다른 ID로 추가한 곡에는 적용하지 않는다.

세 모드의 데이터는 분리되어 있고 선택한 모드만 적용한다. 타임라인의 시각/숫자/키프레임 보기를 바꾸는 것은 애니메이션 모드 변경이 아니다. 모드를 바꾼 뒤에도 이전 모드로 돌아가면 점이 복원된다. 모드 사이 이동은 명시적인 복사/붙여넣기로 수행한다.

## 6. 기존 효과와 합성

기존 등장/퇴장, 반복 모션, 음악 반응형 효과, Now Playing 전용 퇴장과 소스 노출 시간을 유지한다.

Canvas 경로의 합성 규칙은 다음과 같다.

- 위치: 키프레임 위치에 기존 모션의 이동량을 더한다.
- 크기: 키프레임 크기에 기존 모션의 크기 배율을 곱한다.
- 회전: 키프레임 회전에 기존 모션의 회전량을 더한다.
- 투명도: 키프레임 투명도와 기존 페이드 배율을 곱한다. 기본 투명도를 다시 곱해 제곱하지 않는다.
- 키프레임이 없는 속성은 기존 기본값을 사용한다.
- 소스 노출 구간과 숨김 상태는 최종 표시 여부를 제한한다.

오디오 시각화는 기존 효과를 그린 알파 레이어에 키프레임 변형·투명도를 적용한다. CPU와 GPU 미리보기가 같은 어댑터를 사용하고, FFmpeg는 같은 곡선의 수식으로 해당 변형을 수행한다. 영상 소스는 기존 내보내기 제한인 없음/페이드 효과를 유지하면서 키프레임 변형을 추가한다.

크로스페이드와 AutoMix는 `visual_segments()`의 화면 전환 시점에 따라 한 곡을 선택한다. 로컬 시계는 그 곡의 오디오 시계이며 화면을 넘겨받았다는 이유로 0으로 초기화하지 않는다. 공백에는 곡별 키프레임을 적용하지 않는다. AutoMix 분석 결과가 추가되면 편집기의 실행 계획도 갱신하며, 재생 중에는 실제 미리보기 계획과 재생 헤드를 따른다.

## 7. 타임라인과 편집 정책

현재 선택한 요소가 지원하는 속성 레인을 펼쳐 표시한다. 다이아몬드 드래그는 시간을 변경하고, 숫자 편집의 `적용`은 선택한 한 점의 시간·값·구간 보간을 변경한다. `추가`는 현재 재생 위치에 점을 추가한다. 다음 점이 있는 시작점을 선택하고 `그래프`를 누르면 베지어 제어점을 편집할 수 있다. 확대·축소와 현재 뱅크 초기화는 `⋯` 메뉴에서 실행한다.

| 동작 | 조작 |
| --- | --- |
| 점 선택 | 클릭, Ctrl+클릭, 빈 영역 드래그 |
| 시간 이동 | 점 드래그 또는 좌/우 방향키 |
| 복사/붙여넣기 | Ctrl+C / Ctrl+V 또는 버튼 |
| 삭제 | Delete / Backspace 또는 버튼 |
| 이전/다음 점 이동 | Alt+좌/우 또는 이전/다음 버튼 |
| 전체 점 선택 | Ctrl+A |
| 확대/축소 | Ctrl+휠, +/−, 맞춤 |
| 실행 취소/다시 실행 | 기존 프로젝트 Undo/Redo |

스냅은 선택한 FPS 격자와 가까운 점을 사용한다. FPS 격자는 24/25/30/50/60/120/240 중 선택할 수 있고 기본값은 30이다. 격자 변경은 기존 점의 시간을 다시 양자화하지 않는다. 출력 FPS와 별개인 편집 보조 설정이다.

붙여넣기는 복사한 첫 점을 현재 위치에 맞추고 점 사이 간격을 유지한다. 이동/붙여넣기가 기존 점과 충돌하면 데이터를 덮어쓰지 않고 작업을 거절해 안내한다. 초기화는 현재 모드의 현재 곡 뱅크만 삭제하며 확인을 거친다.

속성창의 `◆`는 현재 점, 색이 있는 `◇`는 다른 시각에 점이 있는 속성, 일반 `◇`는 점이 없는 속성이다. 자동 키프레임은 기본 OFF다. OFF에서는 현재 점이 있으면 그 점을, 없으면 기본값을 수정한다. 기본값을 바꾸어도 이미 점이 있는 구간의 평가값은 곡선이 결정할 수 있다. ON에서는 속성창의 수치 변경이 현재 점을 만든다. 다중 선택에서는 공통 기본값만 편집하며 점을 자동 생성하지 않는다.

잠긴 요소의 키프레임은 편집하지 않는다. 숨긴 요소의 데이터는 보존하지만 프레임에는 표시하지 않는다. 위치 이동 자체는 프로젝트 변경이나 Undo 항목을 만들지 않는다. 재생 헤드 이동은 레인 전체를 재생성하지 않고 선과 현재 값만 갱신한다.

## 8. 미리보기와 출력 검증

`app/animation/keyframes.py`가 숫자 평가를 담당한다. Canvas 캡처와 출력 프레임 캐시가 같은 평가 결과를 읽는다. `keyframe_render.py`는 곡선과 화면 소유권을 FFmpeg 수식으로 변환한다. 키프레임이 있는 요소는 정지 화면으로 고정하지 않으며, 기존 위치만 기준으로 한 부분 캡처도 피한다. 키프레임 영상은 정적 GPU 직접 합성 경로를 우회한다.

검증에는 다음을 포함한다.

- 다섯 보간의 Python 평가값과 실제 FFmpeg 픽셀값 비교.
- 키프레임이 있는 위치·크기·회전·투명도를 H.264 MP4로 인코딩하고 다시 디코딩해 Canvas 캡처와 비교. 샘플 프레임 중심 위치 허용 오차 1.5px, 투명도에 따른 채널 최댓값 허용 오차 4/255.
- 크로스페이드의 곡 ID/화면 소유권 전환과 곡별 FFmpeg 수식 비교.
- 시작 오프셋이 있는 영상 소스의 실제 필터 그래프 실행.
- 역방향 탐색 후 기본 속성, 편집 Canvas 위치, 프로젝트 변경 상태가 보존되는지 검사.
- 키프레임 영상의 GPU 직접 합성 우회와 CPU/GPU 공통 오디오 레이어 변형 검사.

이 검사는 모든 소스·음악 반응 설정·GPU 드라이버 조합의 픽셀 동일성을 입증하는 것은 아니다. 실제 사용자 프로젝트의 모든 효과 조합과 장시간 출력은 별도 검증이 필요하다.

## 9. 저장과 호환성

기존 `.pvsproj`/JSON 프로젝트에 키프레임 필드가 없으면 빈 기본 모델로 복원한다. 완전히 기본 상태인 키프레임은 저장 시 필드를 생략해 기존 데이터 모양을 유지한다. 점, 활성화 상태, 선택 모드, 대상 ID와 비활성 모드의 뱅크는 프로젝트와 기존 History/자동 저장 경로에 포함된다.

세 뱅크와 곡 ID의 실제 `.pvsproj` 저장·읽기를 검사했다. 캔버스 크기를 변경하며 콘텐츠를 비례 조정할 때는 모든 뱅크의 X/Y 점도 함께 변환한다. 파일 경로나 PC별 임시 경로를 키프레임 식별자로 저장하지 않는다.

새 키프레임이 들어 있는 프로젝트를 키프레임을 모르는 과거 앱에서 여는 것은 보장하지 않는다. 새 앱에서 기존 프로젝트를 읽는 방향의 호환성을 제공한다.

추가 필수 Python 패키지는 없다. 영상 내보내기에는 기존과 동일하게 FFmpeg가 필요하다.

## 10. 테스트와 UI 확인

자동 테스트는 `tests/test_keyframes.py`, `test_keyframe_rendering.py`, `test_keyframe_workspace.py`에 있다. 관련 기존 속성창 목적지 검사를 새 구조에 맞췄다. 전체 회귀 실행 중 발견한 임시 QImage의 constBits 메모리 수명 오류는 테스트에서 이미지를 보유한 상태로 복사하도록 고쳤다.

최종 전체 실행 결과와 제한은 이 문서 끝의 검증 결과에 기록한다. 원본 실행 로그는 `work/keyframe-isolated-final-suite.log`, 모듈별 로그와 결과 JSON은 `work/keyframe-regression-final/`에 둔다.

UI는 실제 Qt 위젯으로 한국어/영어, 960px/1280px 구성과 125%·150%·200% 배율을 렌더링해 확인했다. 캡처는 `work/keyframe-ui-*.png`에 있다. 이는 물리 모니터·화면 읽기 프로그램·모든 창 높이 조합의 수동 검증을 대체하지 않는다.

참고 성능 측정: 이 환경에서 다섯 속성에 각각 100개 점을 둔 숫자 평가 10,000회가 약 0.075초였다. UI/렌더링 전체 성능 수치로 해석하지 않는다.

## 12. 제한과 후속 확인

- 사용자 베지어 그래프와 추가 속성의 후속 구현·검증은 [별도 문서](2026-11-03-advanced-keyframes.md)를 따른다.
- 키프레임 편집은 한 요소를 중심으로 한다. 여러 요소의 점을 한 번에 편집하는 기능은 제공하지 않는다.
- Canvas 직접 드래그는 기존 기본 속성 편집 동작이다. 자동 키프레임은 속성창 수치 편집에 적용한다.
- 음악 반응형 레이어의 기존 래스터 모션 제한은 유지된다. 모든 기존 효과 조합의 출력 동일성을 자동 검증하지는 않았다.
- 오래된 앱에서 새 키프레임 프로젝트를 읽는 방향의 호환성은 보장하지 않는다.
- 고해상도 영상/시각화의 큰 확대는 기존보다 큰 알파 합성 버퍼와 더 많은 출력 계산을 요구할 수 있다.
- 최초 구현에서는 실제 GPU와 장시간 검증을 수행하지 않았다. 후속 실제 GPU·연속 재생 검증의 조건과 결과는 위 별도 문서에 기록한다. 물리 모니터 입력·접근성 및 모든 대형 프로젝트 조합의 검증을 의미하지 않는다.

### 전체화면 후속 안정화 (2026-11-03)

전체화면 전환 직후 늦게 전달되는 최초 `WindowActivate` 알림이 이미 숨긴 조작 패널을 다시 띄웠다. 레이아웃이 아직 이전 크기에서 전환 중이면 이 패널이 성능 모니터 위에 놓여 기존 검사가 실패했다. GPU 실패 시 CPU 모드로 복귀하는 동안 이벤트를 처리하면 같은 문제가 재현됐다.

`PreviewPresentationController`는 창이 비활성에서 활성으로 실제 전환할 때 조작 패널을 표시하도록 수정했다. 이미 활성 상태일 때의 중복 활성화 알림은 숨김 상태를 유지한다. GPU 포커스 상태 전달과 포인터 추적은 계속 수행하며, Alt+Tab 복귀 때는 패널과 정상 커서를 복구한다.

기존 실패 검사에 패널의 숨김 상태 검증을 추가하고, 지연된 최초 활성화·중복 알림·실제 Alt+Tab 복귀를 구분하는 회귀 테스트를 추가했다. 전체화면 테스트 **18개**, 성능 모니터·GPU 상태·작업자 수명·미리보기 반응성·레이아웃·믹스 전환·키프레임 작업공간 테스트 **44개**가 모두 통과했다. 로그는 `work/fullscreen-monitor-fixed-tests.log`, `work/fullscreen-monitor-regressions.log`다.

이전 전체 실행 결과의 관련 모듈을 최신 재실행 결과로 교체한 집계는 **2,286개 중 2,270개 통과, 16개 건너뜀, 실패 0개**다. 이는 전체 테스트를 다시 실행한 수치가 아니라 원본 전체 실행과 후속 검증을 합친 집계이며, `work/fullscreen-monitor-validation.json`에 근거를 저장한다. 실제 GPU 드라이버와 물리 모니터에서의 수동 검증은 여전히 수행하지 않았다.
