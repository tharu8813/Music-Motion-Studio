# 곡 정보/설정: 노래와 가사 미리보기 UI 및 TTML 노래방 강조

## 기존 문제

`TrackDetailsDialog`의 `노래와 가사 미리보기`는 QLabel 3개에 고정된 이전/현재/다음 1개 큐만 표시하고, 창 크기에 상관없이 줄 수와 QLabel 최대 높이가 고정되어 있었다. TTML을 붙여도 줄 전체를 통째로 현재 가사 색으로 표시했고 단어의 시작/끝 시각을 미리듣기에 활용하지 않았다.

## 개선 결과

- 기존 재생·일시정지·정지·탐색·볼륨·곡별 싱크 보정, 무손실 원본 가사 및 편집 워크플로 유지
- 앨범 커버 썸네일, 곡 제목/아티스트, 라운드 다크 가사 스테이지, LIVE LYRICS 상태 표시와 명확한 현재 줄 강조를 통해 오래된 플레이어 레이아웃 개선
- 가사 뷰포트의 실제 **높이/너비 및 텍스트 줄바꿈 높이**를 측정해 현재 가사 그룹을 먼저 예약하고, 이전/다음 가사는 남는 공간에 최대한 채움
- 이전/다음 가사 수는 고정 설정이 아니라 **대화상자/가사 스테이지 리사이즈에 자동 반응**
- TTML 원문에 `words`(start/end/offset)가 있으면 `LyricsService.word_highlight_ranges`의 실제 단어·음절 진행 좌표를 `QTextDocument`의 부분 클립으로 그려 한 단어 중간까지 밝아지는 효과를 구현
- 겹치는 TTML 구간은 원래의 `LyricsService.active_cue_indices`·`last_ending_cue_indices`를 그대로 사용해 동시에 노래하는 두 줄을 별도 시간으로 그림
- 승인된 번역 텍스트는 기존 `display_cue`로 읽되 **원문 단어 타이밍을 번역문에 임의로 적용하지 않음**
- TTML 파일이라도 단어 시간 정보가 없다면 기존 LRC와 마찬가지로 **줄 동기화** 처리
- QMediaPlayer 위치 이벤트가 성긴 Windows에서도 실제 TTML 단어 색이 자연스럽게 진행되도록 **33ms 간격(약 30FPS)** 갱신. 가사 탭에서 노래 재생 중일 때만 타이머 활성화
- 같은 현재 줄에서는 **주변 가사 레이아웃 캐시**로 반복 레이아웃/텍스트 변경 방지. 가사 변경, 타이밍 보정, 창 리사이즈, 줄 이동 시 자동 갱신
- 긴 가사 수천 줄에서도 매 위치 업데이트 시 재구성 대상은 현재 줄 부근 최대 20개씩으로 제한

## 주의

단어별 시간은 TTML 데이터에 실제로 명시된 값만 사용한다. 단순한 줄 시작/종료만 있는 TTML에서 단어 속도를 추정하지 않는다.

이 기능은 독립된 곡 설정 UI에서만 동작한다. Canvas 출력·FFmpeg·NVENC·타 프로젝트 모델·저FPS 내보내기 실험 코드에는 **영향 없음**.

## 검증

`tests/test_track_lyrics_preview.py`:

- 좁고 넓은 가사 뷰포트의 자동 문맥 표시 개수 차이
- 줄바꿈이 많은 문장에서 표시 개수와 클리핑 계산
- TTML 2단어에서 시작/중간/후반 시간의 부분 강조 구간
- QLabel Qt offscreen 실제 픽셀 그림 비교
- 겹치는 두 TTML 가사가 현재 화면에 동시에 있고 서로 다른 단어 시각이 적용되는지
- 사용자 가사 타이밍 보정 후 표시 시각 변경
- UI 리사이즈 시 이전·다음 자동 재배치
- 타이머 수명주기와 동일한 줄의 문맥 레이아웃 캐시

기존 `tests.test_lyrics_overlap`의 곡 설정 미리보기 겹침/held line 동작 회귀 테스트도 Windows CI의 FFmpeg 설치 이전 별도 단계에 포함한다.

실제 Windows 오디오 재생 장치에서 음악에 맞는 부드러운 30FPS 강조를 최종 확인하는 것은 사용자의 UI 검수 단계에서 수행할 수 있다.
