# 가사 렌더링 계산 재사용과 설정 요약

기존 화면과 내보내기 결과를 유지하기 위해 글자 배치, 효과, 블러, 색상, 타이밍, 해상도와 품질 설정은 바꾸지 않았다. 이번 변경은 동일한 입력으로 반복하는 글꼴/폭/행 높이 계산을 재사용한다.

## 변경

- `SourceItem`마다 줄별 글꼴 최대 64개, 글자 너비 최대 256개를 보관한다. 한도를 넘으면 가장 오래 사용하지 않은 항목부터 교체한다.
- 기존 `text_font`, `QFontMetricsF.horizontalAdvance`, 행 높이 수식을 그대로 사용한다. 반환한 글꼴을 수정해도 캐시에 영향을 주지 않도록 복사한다.
- 글꼴, 자간, 대소문자, 굵기, 줄 간격 등 기존 리소스 키가 바뀌면 캐시를 비운다. 프로젝트 저장 형식이나 기본 설정은 변경하지 않는다.
- 자막 전환 설정에 실제 적용되는 효과·방향·이전/다음 줄 수를 표시한다. 미리보기 줄 수가 영상 배치를 바꾸지 않는다는 안내와 ‘설정 적용’, ‘변경 취소’ 버튼을 제공한다.

## 검증

작업 시작 시점의 작업 트리 렌더러를 `work/lyrics-optimization-2026-10-29/*.before.py`에 보관했다. 비교 대상은 Git HEAD가 아니라 그 시점에 이미 적용되어 있던 개선을 포함하는 코드다.

- 변경 전/후 1,024개 프레임의 크기·포맷·SHA-256이 모두 일치했다. 8개 효과 × 4방향 × 기본/고급 모드 × 2해상도(640×360, 1920×1080) × 8시점이다. 한영·이모지·여러 줄·단어 타이밍·인트로/간주·외곽선·줄별 스타일·역할별 블러가 포함된다.
- 2,000개 이중 언어 큐의 90프레임 벤치마크도 rise/glow/karaoke 전부 기존 프레임 해시와 일치했다. 같은 프로세스에서 순서를 교차한 3회 반복에서도 일치했다.
- 가사, TTML, 내보내기 프레임 동등성, 프레임 상태, 속성 패널 관련 기존 테스트 206개와 새 회귀 테스트 3개가 통과했다. 새 테스트는 계산 재사용, 캐시 한도/초기화/복사 안전성, 캐시 사용 여부의 픽셀 동등성, 미리보기 조절 시 원본 설정 보존을 확인한다.
- 한국어 설정창을 1200×800으로 렌더링해 요약/미리보기/버튼 배치를 확인했다. `work/lyrics-optimization-2026-10-29/settings-summary.png`.

단일 1,024프레임 실행 시간은 10.76초에서 9.45초였다. 다만 교차 반복의 프레임 중앙값은 rise 3.363→3.828ms, glow 6.285→5.617ms, karaoke 4.038→3.932ms로 편차가 있었다. 모든 효과에서 일정한 속도 향상을 보장하는 근거로 삼지 않는다. 확정 가능한 개선은 같은 글자 너비를 30번 요청할 때 측정 호출이 1번으로 줄고, 캐시 크기가 제한된다는 점이다.

픽셀 동등성 검증은 압축 전의 공용 미리보기/내보내기 렌더링 경로에 대한 것이다. 모든 프로젝트, 시스템 글꼴 환경, GPU, 인코더 조합의 완성 영상 파일까지 바이트 단위로 같다고 보장하는 검증은 아니다. 추가 최적화가 필요하면 먼저 동일한 방식으로 기준 프레임을 확보한다.
