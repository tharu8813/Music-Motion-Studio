# IVY 실제 내보내기 병목 측정 — 2026-10-26

## 결과

현재의 주요 제약은 Qt에서 화면을 준비하는 속도다. 준비된 입력을 주었을 때 최종
합성·NVENC 인코딩은 약 83 FPS였고, 실시간 화면 공급을 포함한 전체 경로는 약 30 FPS였다.
캡처 생략 최적화는 이번 단축본의 전체 시간을 약 13.5% 줄였다.

| 비교 | 영상 길이 / 프레임 | 소요 시간 | 처리 속도 |
|---|---:|---:|---:|
| 캡처 생략 끔 | 20초 / 1,200 | 46.219초 | 25.96 FPS |
| 현재 개선판, 측정 1 | 20초 / 1,200 | 40.094초 | 29.93 FPS |
| 현재 개선판, 독립 확인 | 20초 / 1,200 | 39.844초 | 30.12 FPS |
| 준비된 입력의 최종 합성·인코딩 단계 | 20초 / 1,200 | 14.383초 | 83.43 FPS |

현재 개선판의 두 측정 중앙값은 39.969초다. 마지막 행은 화면·시각화·오디오를 미리
준비한 별도 경로의 최종 단계만 잰 값이므로, 전체 내보내기 시간과 직접 비교하면 안 된다.
대조군은 현재 코드에서 캡처 생략만 끈 것이며 과거 설치 파일 전체의 벤치마크는 아니다.

캡처 생략 켬/끔 두 영상의 1,200개 프레임을 실제 디코딩했다. 픽셀 MD5와 타임스탬프가
모두 동일했으며, 프레임 기록 전체의 SHA-256은 두 영상 모두 다음 값이다.

`714055cd9289b6aea4a64e253fc350f711584039e34c7c36cd06c86e6531f3bc`

## 어느 쪽이 기다리는가

마지막 독립 측정 39.844초에서 다음 값을 얻었다.

| 측정 범위 | 누적 시간 | 해석 |
|---|---:|---|
| Canvas 프레임 생성·전달 | 37.582초 | 메인 캡처 루프가 대부분의 시간을 사용 |
| Canvas 상태 적용·캡처 | 34.131초 | 위 범위에 포함 |
| 장면 래스터화 | 19.962초 | 캡처 시간에 포함 |
| 캡처 스레드 자신의 CPU 시간 | 23.203초 | 대기·다른 스레드 실행 시간은 제외 |
| Canvas 입력 큐에서 기다린 시간 합계 | 2.314초 | base / layer:0 / layer:1 합계 |
| 파티클·시각화 입력 큐 대기 | 각 25.836 / 32.203초 | 다른 입력의 진행을 기다리는 시간이 큼 |

이는 화면 캡처가 FFmpeg의 입력 소비를 오래 기다리는 상황보다, 최종 FFmpeg와
시각화 공급자가 Canvas의 다음 화면을 기다리는 상황을 뒷받침한다.
스레드 간 Python/Qt 실행 경쟁도 포함될 수 있으며, GIL만의 영향은 분리하지 않았다.
동시에 실행되는 작업과 포함 관계가 있는 타이머를 합산해 전체 시간으로 해석하면 안 된다.

## 함수별 확인과 임시 실험

멀티스레드 실제 내보내기에는 별도 wall/CPU 타이머를 사용했고, 함수 상세 분석은 캡처만
따로 실행해 보완했다. 30–33초 장면의 단일 스레드 캡처 프로파일에서 가사 블러 래스터,
pixmap 그리기, 이미지 초기화가 큰 비용으로 확인됐다. 벤치마크의 픽셀 해시 계산 비용은
제품 렌더링 비용으로 세지 않았다. 다음 개선 후보는 가사 블러/래스터 재사용과 레이어의
전체 면적을 반복해서 그리는 비용이며, 변경 시 회전·확대·알파까지 픽셀 비교가 필요하다.

| 임시 실험 | 비교 결과 | 처리 |
|---|---|---|
| Windows 파이프 쓰기 조각을 1 MiB에서 프레임 전체 크기로 확대 | 상세 프로파일러 사용 시 48.734 → 48.125초 | 전체 차이가 작아 제품 코드에 미반영 |
| 내보내기 동안 앨범 이미지·색상 조회 결과 재사용 | 40.094 → 38.891초, 단일 비교 약 3% | 주요 병목으로 판단하지 않고 제품 코드에 미반영 |

상세 cProfile 사용 자체가 시간을 늘리므로 위 파이프 실험 수치를 프로파일러 없는
39.844/40.094초와 섞어 비교하지 않았다. 추가 확인 중 프레임 해시 디코딩과 겹친
42.312초 실행도 깨끗한 시간 비교에서는 제외했다.

## 범위와 보존

- Intel Core i5-14600KF, 논리 프로세서 20개, RAM 32 GB, Windows.
- Python 3.12.15 / PySide6 6.11.1, 실제 설치된 FFmpeg와 NVIDIA 인코더 사용.
- 1920×1080 / 60 FPS / NVENC / CRF 14 / medium / AAC 320k / 작업 모드 자동.
- `IVY.pvsproj`를 별도 임시 캐시에 읽고 첫 활성 곡을 20초로 줄인 작업 복사본으로 테스트했다.
  전체 트랙 수·진행 표시·종료 애니메이션은 단축본을 따른다. 21분 전체를 완주한 측정은 아니다.
- Qt offscreen으로 같은 Canvas/내보내기 코드를 실행했다. 설치본의 데스크톱 창 표시 비용을
  그대로 재현한 측정은 아니다. 다른 사용자 앱의 부하는 고정하거나 종료하지 않았다.
- 실제 내보내기는 사용자 허용에 따라 취소했다. 테스트 결과는 `work/ivy-export-profile/`에
  별도 저장했고, 프로젝트와 기존 완성 영상은 덮어쓰지 않았다.
- 원본 프로젝트 SHA-256 보존 확인:
  `cc834873767748a183bc7d35b8776b04c8e34493069048cb1cacaf8bffdb9a98`.
- 이번 진단에서는 제품 코드를 추가로 변경하거나 설치 파일을 교체하지 않았다.
