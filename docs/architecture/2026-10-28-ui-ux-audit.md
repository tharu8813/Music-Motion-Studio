# Playlist Canvas UI/UX 및 전반 점검 — 2026-10-28

후속 구현: [2026-10-29 작업 공간 사용성 개선](2026-10-29-workspace-usability.md). 아래는 개선 전 점검 기록이며 현재 구현·검증 결과는 후속 문서를 참고한다.

이번 점검의 핵심 판단은 **기능 안내가 전반적으로 없는 앱은 아니지만, 작은 화면에서의 작업 공간 확보와 초급·고급 기능의 단계적 노출이 부족하다**는 것이다. 음악 추가의 빈 상태 안내, 프리셋 미리보기, 가사 검색의 단계 표시, AutoMix의 기본·고급 구분은 좋은 기반이다. 반면 캔버스가 잘리거나 설정의 의미가 사라지는 문제는 실제 작업을 방해한다.

점검은 현재 작업 트리 기준이다. 기존 가사·TTML 관련 미커밋 변경을 포함해 확인했고, 애플리케이션 소스와 기존 테스트는 수정하지 않았다. 아래 내용은 확인된 결함, 사용성 개선 제안, 추가 검증 필요 사항을 구분한다.

**점검 방법과 범위**

- Python 3.14.10 / PySide6, 프로젝트의 기존 `.venv` 사용.
- 초기 편집기, 시작 화면, 새 프로젝트, 내보내기, 설정 6개 탭, 곡 정보 5개 탭, 가사 검색, 가사 편집 4개 페이지, 소스 속성, AutoMix 기본·고급 화면을 Qt offscreen으로 렌더링했다. 총 34개 화면 상태를 저장했다.
- 편집기 크기 1560×920 → 1100×680 → 1366×720으로 변경해 비교했다. 새 프로젝트와 내보내기는 한국어·영어 모두 확인했다.
- `QAccessible`로 실제 입력 컨트롤의 접근성 이름과 설명을 조회했다. 스크린리더 프로그램을 직접 조작한 검사는 아니다.
- 기존 구조 그래프는 2026-09-30 자료이므로 화면 간 연결의 길잡이로만 사용하고, 결론은 현재 소스와 렌더링 결과를 근거로 삼았다. 그래프 조회 자체는 모델 API를 사용하지 않았다.
- 기존 전체 테스트 러너와 `pip check`를 실행했다. 테스트 결과는 별도 JSON·로그에 보관한다.
- 화면 캡처 중 일부는 상태별 표시를 비교하기 위해 페이지를 직접 선택한 것이다. 모든 화면이 실제 사용자 조작만으로 이어지는 전체 여정을 검증했다는 의미는 아니다.

**1. 창 크기를 바꾸면 전체 캔버스를 보던 상태가 깨진다**

큰 창에서 배율은 약 58.7%였다. 1100×680으로 줄이면 캔버스 뷰포트는 370×236으로 줄지만, 화면에 매핑된 아트보드는 여전히 753×424다. 제목과 진행 막대의 일부가 잘린다. 다시 1366×720으로 늘려도 뷰포트 636×262에 아트보드 753×424가 남는다.

`fit_artboard()`는 있지만 창 크기 변경 시 이를 유지할 상태가 없다. 사용자는 작업 요소가 사라졌거나 캔버스가 이동했다고 생각할 수 있다. `Ctrl+0`으로 복구할 수 있으므로 데이터 손실 문제는 아니다.

권장 변경: `화면에 맞춤` 상태와 사용자가 지정한 확대 상태를 구분한다. 맞춤 상태에서는 창·패널 크기 변화 시 다시 맞추고, 사용자가 확대했을 때만 배율을 보존한다. 작은 창에서는 빈 플레이리스트 높이도 줄여 중앙 작업 공간을 확보한다. 사용자가 직접 확대해 둔 상태를 무조건 초기화해서는 안 된다.

근거: `app/canvas/live_canvas.py:1227`, `app/ui/main_window.py:214`, `app/ui/main_window.py:1604`, `app/ui/main_window.py:1671`.

화면: [1100×680 편집기](../../work/audit-2026-10-28/02-editor-empty-small.png), [1366×720 편집기](../../work/audit-2026-10-28/03-editor-laptop.png).

**2. 최소 크기와 고정 구조가 작은 화면·확대 배율에 취약하다**

메인 창의 최소 크기는 1100×680이다. 새 프로젝트는 820×641로 렌더링되며 내용의 최소 높이도 641이다. 내보내기 창은 820×667로 열리고 내용 최소 높이는 640이다. 새 프로젝트와 내보내기는 본문 전체를 스크롤할 구조가 아니다.

예를 들어 1366×768 화면을 125%로 사용하는 경우 논리 공간은 약 1093×614이고, 작업 표시줄과 창 테두리까지 고려하면 실제 내용 공간은 더 작다. 위 최소 크기를 수용하기 어렵다. 이 배율의 실물 모니터에서 직접 재현하지는 않았으며, 측정한 최소 크기와 논리 해상도 계산에 따른 판단이다.

권장 변경: 주요 대화상자는 본문 스크롤과 고정 하단 버튼을 사용하고, 화면의 `availableGeometry()` 안에서 열리도록 한다. 메인 편집기는 너비·높이에 따라 보조 패널을 접거나 크기를 조정한다. 검증 기준에는 1366×768의 100%·125%, 1920×1080의 150%를 포함한다.

근거: `app/ui/main_window.py:451`, `app/dialogs/new_project_dialog.py:91`, `app/dialogs/export_settings_dialog.py:171`.

**3. 내보내기 창에 의미를 알 수 없는 체크박스가 있다**

용도 선택 아래의 오른쪽에 체크 표시만 보인다. 한국어·영어에서 모두 동일하다. `advanced_check`를 만들고 고급 영역 표시와 연결하지만, `retranslate()`에서 텍스트를 지정하지 않는다. 툴팁과 접근성 이름도 비어 있다. 사용자는 무엇을 켜고 끄는지 알 수 없다.

권장 변경: `고급 인코딩 설정 표시`라는 이름을 제공하거나, 설명이 있는 접기/펼치기 버튼으로 교체한다. 상태가 바뀌면 표시되는 영역과 버튼 문구가 함께 바뀌어야 한다.

근거: `app/dialogs/export_settings_dialog.py:92`, `:132`, `:221`, `:620`.

화면: [현재 내보내기 창](../../work/audit-2026-10-28/06-export.png).

**4. 내보내기가 권장값을 고른 후에도 전문 지식을 요구하는 화면처럼 보인다**

`권장 · 대부분의 영상`을 선택한 상태에서도 비디오 인코더, CRF, 인코딩 속도, AAC 비트레이트가 모두 보인다. `advanced_group`과 `advanced_check`가 처음부터 활성화되어 있기 때문이다. 초보자는 권장값만으로 충분한지, 모든 항목을 이해하고 결정해야 하는지 판단하기 어렵다.

권장 변경: 기본 화면에는 출력 종류·파일 위치·해상도·FPS·용도와 짧은 결과 요약을 남긴다. 고급 설정은 기본적으로 접고, 직접 조정한 경우에만 `사용자 설정` 상태를 분명하게 표시한다. AutoMix가 이미 제공하는 기본·고급 구분을 앱 전체에 일관되게 적용할 수 있다.

근거: `app/dialogs/export_settings_dialog.py:216`, `:217`, `:305`.

**5. 오른쪽 속성 패널의 기능 발견성이 떨어진다**

속성은 최대 8개 범주를 가로 탭으로 표시한다. 패널 안쪽 너비와 탭 총너비가 비슷하거나 더 작아, 창 크기와 선택 요소에 따라 뒤쪽 탭이 화살표 뒤로 숨는다. 가사 요소에서는 `자막/가사` 같은 긴 첫 탭이 추가되어 더욱 두드러진다. 사용자는 현재 보이는 범주가 전부라고 오해할 수 있다.

또한 속성 패널 전체가 바깥 스크롤 영역에 들어 있어 긴 설정을 읽을 때 제목·탭까지 함께 이동한다. 기본 작업에서 탭 스크롤과 본문 스크롤을 함께 이해해야 한다.

권장 변경: 선택 요소 이름과 탐색부는 고정하고 속성 본문만 스크롤한다. 좁은 패널에서는 범주 선택 드롭다운 또는 2행 탐색으로 전환한다. 패널을 넓히는 것만으로 해결하면 캔버스가 더 좁아지므로 피한다.

근거: `app/inspector/source_inspector.py:162`, `:197`, `:201`, `:258`, `:851`.

화면: [가사 요소 속성](../../work/audit-2026-10-28/16-lyrics-source.png).

**6. 도움말이 있어도 입력란의 접근성 이름은 충분하지 않다**

QAccessible 조회에서 속성 패널의 이름, X, Y, 너비, 높이, 회전, 크기 입력란은 접근성 이름이 비어 있었다. 설명은 전달된다. 내보내기에서는 서로 다른 입력란 여러 개가 `출력 파일` 또는 `고급 인코딩 설정` 같은 그룹명으로 읽힌다. 새 프로젝트에서도 이름·작성자 입력란이 모두 `프로젝트 정보`라는 이름을 받는다.

권장 변경: 보이는 라벨과 입력란을 `setBuddy()`로 연결하고, 컨트롤별 `setAccessibleName()`을 지정한다. 상세 설명은 기존 `setAccessibleDescription()`에 유지한다. 스핀박스 내부 편집창을 별도 입력란으로 중복 집계하지 않도록 접근성 검증도 컨트롤 단위로 해야 한다.

근거: `app/inspector/source_inspector.py:755`, `:785`, `:791`; 각 대화상자의 폼 라벨·입력란 생성부. 실제 조회 결과는 `work/audit-2026-10-28/ui-metrics.json`에 저장했다.

**7. 가사가 없는 상태의 안내가 영상 내용처럼 보인다**

한국어 UI에서 가사 요소를 추가하면 캔버스에 `Lyrics are not available for this track.`이 나타난다. 속성의 요소 이름도 `Lyrics`다. 가사 연결이 필요한 상태라는 설명과, 가사가 없는 곡에 표시할 실제 대체 문구가 한 화면에서 구분되지 않는다.

이 문구는 단순한 편집기 안내가 아니다. `Source.subtitle_fallback`의 기본값이고 캔버스 스냅샷과 내보내기 캡처가 사용하는 경로에도 포함된다. 따라서 사용자가 안내로만 생각한 문구가 영상에 들어갈 여지가 있다. 이번 점검에서 이 조건의 최종 MP4를 새로 만들어 확인하지는 않았다.

권장 변경: 편집 화면에는 `연결된 가사 없음 · 곡에 가사를 연결하세요`라는 상태와 연결 동작을 제공한다. 영상에 들어갈 대체 문구는 별도 필드로 구분하고, 출력 여부를 명시한다. UI 언어를 바꿀 때 사용자가 작성한 영상 문구를 자동 번역하거나 덮어써서는 안 된다.

근거: `app/ui/main_window.py:2260`, `app/models/source.py:202`, `app/canvas/renderers/lyrics_renderer.py:64`, `app/preview/canvas_snapshot.py:948`, `app/preview/export_canvas_capture.py:444`.

**8. 작은 설명과 상태 텍스트의 가독성을 개선할 여지가 있다**

기본 UI 글자는 12px, 설명·상태는 주로 11px, 일부 배지·범주는 10px다. 낮은 채도의 회색을 넓게 사용해 필수 안내와 보조 정보의 위계도 약한 부분이 있다. 모든 설명이 저대비라는 의미는 아니며, 대비율 미달을 일괄 판정하지 않았다.

권장 변경: 화면 글자 크기를 조절하는 기능을 추가하고, 오류·준비 상태·다음 동작 안내는 일반 설명보다 읽기 쉽게 표시한다. 글자만 키우면 기존 고정 크기 창이 더 넘칠 수 있으므로 2번의 레이아웃 개선과 함께 검증한다. 영상 안의 글자 크기와 앱 UI 글자 크기는 구분한다.

근거: `app/ui/studio.qss:6`, `:28`, `:107`, `:204`, `:292`.

**9. 마지막 실행 동작의 강조가 일관되지 않다**

새 프로젝트의 `프로젝트 만들기`, 설정의 `저장`, 메인 창의 `내보내기`는 강조색을 사용한다. 반면 내보내기 대화상자의 `내보내기 시작`은 일반 회색 버튼이다. 같은 화면의 `권장 설정으로 되돌리기`와 시각적 차이가 작다.

권장 변경: 활성화된 최종 실행 버튼에 기존 `primary` 스타일을 적용한다. 되돌리기·취소·보조 설정은 보조 동작으로 유지한다. 비활성화 상태와 포커스 상태도 함께 확인한다.

근거: `app/dialogs/export_settings_dialog.py:117`, `:665`, `app/ui/studio.qss:53`.

**UI 이외에 확인한 사항**

- 프로젝트 저장은 임시 파일 작성 후 교체하는 구조이고, 임베드 미디어의 누락·디스크 공간을 확인한다. 미디어 경로와 아카이브 크기 제한도 있다. 이 점검 범위에서 새로 입증한 데이터 손실 결함은 없다.
- 프로젝트를 바꾸기 전 저장·버리기·취소 분기가 존재한다. 자동 저장·복구는 별도 서비스와 테스트로 관리된다.
- 앱 업데이트는 허용된 GitHub 자산 경로, 선언된 크기, SHA-256을 검증한다. FFmpeg ZIP에는 경로 이탈·파일 수·해제 크기 검사 코드가 있다.
- 가사 검색에는 응답 크기 제한, 캐시 제한, 타임아웃이 있고, KRC 압축 해제에도 크기 제한이 있다. 외부 서비스의 실제 응답 성공률을 측정한 것은 아니다.
- 의존성 검사 `pip check`는 `No broken requirements found.`로 통과했다. 취약점 데이터베이스를 이용한 보안 감사는 수행하지 않았다.
- 메인 창 파일은 현재 5,489줄이다. 컨트롤러 분리는 진행되어 있지만 기능 연결이 한곳에 많이 남아 있다. 새 기능을 추가할 때 UI 구성·사용자 명령·비동기 작업 상태를 계속 분리하는 편이 회귀 위험을 줄인다. 이번 점검만으로 전면 재구성을 권하지 않는다.

**테스트와 문구 일관성**

전체 실행 결과는 **151개 모듈 중 150개 통과, 1개 실패**다. 테스트 1,978개 중 1,903개 성공, 2개 실패, 73개 건너뜀이며 실행 시간은 약 13분이다. 실패한 모듈은 아래 두 문구 기대값 차이를 포함한 `test_main_window` 하나다. 나머지 모듈은 저장·복구, 플레이리스트, 미리보기, 내보내기, AutoMix, 가사·TTML, 작업 스레드 종료, UI 응답성 검사를 포함해 통과했다. 각 모듈 안의 환경 의존 테스트가 건너뛴 경우도 있으므로 모든 경로를 실제 실행한 것으로 해석해서는 안 된다.

현재 `test_main_window`에서 확인된 실패 2개는 실행 오류가 아니라 명칭 변경 뒤 남은 기대 문구 차이다.

- `test_menu_bar_is_grouped_and_fully_localized`: 기대 `LRC 파일 생성기`, 실제 `가사/자막 편집기`.
- `test_help_dialog_has_a_tab_per_window_with_tagged_topics`: 기대 `가사 편집기`, 실제 `가사/자막 편집기`.

현재 가사·자막·TTML까지 다루는 범위를 고려하면 새 명칭 자체가 잘못됐다고 판단할 근거는 없다. 제품에서 사용할 명칭을 정하고 메뉴·도움말·테스트를 같이 맞추는 것이 적절하다. 단순히 테스트를 통과시키려고 이전 문구로 되돌리는 것은 권하지 않는다.

**권장 수정 순서와 완료 기준**

1. 설명 없는 체크박스를 수정하고 내보내기 고급 옵션을 기본적으로 접는다. 처음 내보내는 사람이 권장값으로 완료할 수 있어야 한다.
2. 캔버스 맞춤 상태와 작은 화면 레이아웃을 개선한다. 창 크기를 바꿔도 맞춤 상태의 전체 캔버스가 보이고, 주요 창의 하단 실행 버튼에 항상 접근할 수 있어야 한다.
3. 속성 탐색과 접근성 라벨을 정리한다. 뒤쪽 범주를 발견할 수 있고 위치·크기 입력란을 키보드와 접근성 도구로 구분할 수 있어야 한다.
4. 가사 미등록 상태와 실제 출력 문구를 분리한다. 무엇이 완성 영상에 포함되는지 사용자가 알 수 있어야 한다.
5. 글자 크기·버튼 강조·명칭과 관련 테스트를 맞춘다.

**검증 한계**

offscreen 검증이므로 실제 Windows 모니터의 DPI 전환, 시스템 스크린리더, 마우스 사용감, 실제 GPU 렌더링 품질·속도는 확정하지 않았다. 장시간 4K 내보내기·배포 설치·실제 외부 가사 검색도 이번 점검에서 새로 실행하지 않았다. 기존 테스트에서 통과하거나 건너뛴 항목은 최종 집계에 구분되어 있으며, 테스트 통과를 이 조건들까지 검증했다는 의미로 확대하지 않는다.
