# 줄바꿈 가사의 연속 스크롤

## 문제

기존 세로 가사는 표시할 큐의 배치와 미리 준비한 큐의 진입 이동을 따로 계산했다. 긴 가사가 자동 줄바꿈되면 표시 범위가 달라지고, 준비된 가사가 인접한 가사와 다른 거리로 이동할 수 있었다. 이전 가사의 보관 범위도 현재 표시 줄 수와 한 개의 퇴장 큐에 의존했다.

현재 가사의 높이에 따라 기준 위치를 화면 안쪽으로 제한하는 처리 역시 전환 첫 프레임에 바로 적용됐다. 실제 Qt 렌더러로 긴/짧은 가사를 번갈아 표시한 비교에서, 기준 위치가 위쪽/아래쪽인 사례는 전환 경계에서 최대 91.6px의 위치 차이를 보였다. 이는 작업 전 Git HEAD의 렌더러·캡처 코드와 수정된 코드를 같은 작업 트리의 나머지 코드 및 글꼴로 비교한 결과다.

## 배치

- 세로 방향은 하나의 가사 띠에서 현재 큐 중심까지 이동하는 방식으로 계산한다. 자동 줄바꿈의 이어지는 행은 글자 높이만큼, 원래 입력된 줄바꿈과 큐 사이는 설정한 줄 간격을 포함해 배치한다.
- 현재 큐의 앞뒤 표시 범위와 전환 직전의 범위를 함께 준비한다. 양쪽에 추가로 두 큐를 보관하며, 전체 트랙의 가사를 이미지나 거대한 텍스트 레이아웃으로 만들지 않는다.
- 자동 표시 범위는 기준 위치 양쪽의 실제 공간과 큐 높이로 각각 계산한다. 긴 가사가 남은 공간보다 크더라도 화면에 들어오는 일부를 준비한다.
- 표시 수를 직접 지정하면 그 범위가 작은 표시 창이 된다. 이전 창과 다음 창의 경계를 보간하고 가사가 그 아래로 지나가게 하며, 새 가사를 별도로 화면 가장자리까지 밀거나 빈 공간에서 페이드 인시키지 않는다.
- 높이가 바뀌어 기준 위치를 옮겨야 할 때도 직전 기준 위치에서 새 기준 위치로 보간한다. 자동 범위의 거리별 블러와 투명도는 보관한 큐 수 대신 화면 내 실제 거리를 기준으로 계산한다.
- 보관 범위가 바뀔 때의 부동소수점 오차로 Qt의 글자 래스터 위치가 달라지지 않도록 최종 세로 위치를 소수점 여섯 자리로 정규화한다.

역할별 스타일, 단어별 강조, 원본 줄별 스타일과 문자 위치, 간주 표시를 유지한다. 사용자가 선택한 순차 이동 효과는 기존의 순차 지연을 유지한다. 가로 방향의 진입 처리와 이전·다음 가사를 모두 숨긴 단독 현재 가사 모드는 기존 경로를 사용한다. 프로젝트 저장 필드와 기본 설정은 추가하거나 변경하지 않는다.

## 검증

`tests/test_lyrics_continuous_strip.py`는 실제 앱 글꼴을 등록하고 Qt 렌더러를 실행한다.

- 긴/짧은 큐 및 원래 두 줄인 큐를 섞어 위/아래 방향과 기준 위치 5%/50%/95%에서 전환 직전·직후의 위치 연속성을 검사한다. 타임스탬프 판정의 0.5ms 허용 오차 밖인 1ms 전을 비교한다.
- 일반 전환에서 인접 행이 같은 거리로 이동하는지, 자동 줄바꿈 행 사이가 조밀하게 유지되는지 검사한다.
- 자동 범위 변경 시 거리별 블러가 튀지 않는지 검사한다.
- 전체 가사를 모두 배치한 기준 이미지와 주변만 준비한 이미지가 동일한지 검사한다. 위/아래 방향, 블러·거리별 투명도, 서로 다른 높이의 큐 및 전환 중간 시점 14개를 포함한다.
- 2,000개 큐에서 준비 범위와 줄바꿈 계산이 화면 주변으로 제한되는지 검사한다.
- 역방향 탐색의 재현성, 두 배 해상도 캡처, 미리보기와 내보내기의 이미지 일치, 캡처 후 원본 상태 복원을 검사한다.

가사·TTML·자동 표시 수·프레임 상태·내보내기 관련 모듈은 다음 명령으로 실행한다. Windows 샌드박스에서는 `TEMP`, `TMP`, `TMPDIR`를 작업 폴더 안의 쓰기 가능한 경로로 먼저 지정한다.

```powershell
.\.venv\Scripts\python.exe scripts/run_tests.py test_lyrics_ test_auto_line_counts test_ttml_lyrics test_export_frame_equivalence test_frame_state test_render_plan test_export_plan --report work/lyrics-scroll-tests-final.json
```

수정 전후 실제 프레임 비교 스크립트는 `work/lyrics_scroll_visual_check.py`, 접촉 시트·애니메이션과 위치 비교 결과는 `work/lyrics-scroll-review/`에 있다. `work/`는 저장소 추적 대상이 아닌 로컬 검증 자료다.

최종 실행은 257개 중 256개 통과, 1개 실패였다. 실패한 `test_comparison_is_tabular_and_highlights_changed_rows`는 이번 작업 전에 이미 수정되어 있던 비교창 색상(`#433c30`)과 기존 테스트 기대값(`#40392b`)의 불일치다. 해당 비교창·색상·테스트는 이 작업에서 변경하지 않았다. 새 연속 스크롤 테스트 8개와 나머지 관련 렌더링·내보내기 검사는 통과했다.
