# Windows Codex와 AgentCraft 환경 일치 적용안

2026-11-05 기준. 현재 상태는 **스킬 원본 공유 완료, 도구 환경 일치는 미완료**입니다. 이 변경은 읽기 전용 점검 도구와 적용안만 제공합니다. 사용자 승인 전 전역 적용은 하지 않습니다.

## 소유 저장소와 변경 범위

현재 `playlist_project`는 플레이리스트 앱 저장소이며 AgentCraft 호스트 소스가 없습니다. 실제 연결 구현 대상은 `C:/Users/wlqor/Desktop/agentcraft`의 `foreman/src/agents/codex/engine.ts`, `find.ts`, `foreman/src/config.ts`입니다. t2/t3 조사에서 해당 저장소의 루트 AGENTS.md/CLAUDE.md는 발견하지 못했습니다. 실제 수정 전 해당 저장소의 최신 지침과 작업 지원 여부를 다시 확인해야 합니다. 별도 저장소 수정 필요성을 리드에 보고했으며 이 브랜치에서는 앱 코드, 외부 저장소, 전역 설정을 수정하지 않았습니다.

상세 근거는 [스킬 진단](codex-skill-parity.md), [도구 진단](codex-tool-parity.md)에 있습니다.

## 현재 적용할 최소 구성

- 기존 `~/.codex/skills`, `~/.agents/skills`를 그대로 사용합니다. 복제·동기화·junction 추가가 필요하지 않습니다. 명시적으로 비활성화된 `hatch-pet`은 유지합니다.
- 현재 AgentCraft는 사용자 MCP와 플러그인을 thread 설정에서 모두 끕니다. 설정 파일을 복사하거나 새로운 미지원 JSON 키를 추가해도 연결되지 않습니다. 따라서 이 브랜치에 가짜 활성화 설정이나 적용 명령은 넣지 않습니다.
- CLI 차이가 확인될 때만 기존 `--codex-path` 또는 `AGENTCRAFT_CODEX_PATH`를 사용하는 안을 검토합니다. 경로 지정만으로 도구 차단이 해제되지는 않습니다.

## 안전한 재점검

저장소 루트에서 Python 3.11 이상으로 실행합니다. 패키지 설치는 없습니다.

```powershell
python scripts/check_codex_environment.py
python -m unittest discover -s tests -p test_codex_environment_inventory.py
```

다른 홈을 검사하려면 `--codex-home <Codex 홈>`과 `--agents-skills <기존 스킬 폴더>`를 명시합니다. 기본 Codex 홈은 현재 프로세스의 CODEX_HOME 또는 `~/.codex`입니다. 이것은 실행 중 Foreman의 실효 홈을 자동 검출한 값이 아닙니다.

점검 도구는 config.toml을 TOML로 읽고 스킬 경로·폴더 이름·명시 비활성 여부, MCP/플러그인의 식별자와 enabled만 출력합니다. enabled가 null이면 설정에 그 값이 없다는 뜻이며 활성 판정이 아닙니다. 인증 파일, 환경 값, 명령 인자, 세션 DB는 읽거나 출력하지 않습니다. 서버/CLI/플러그인을 실행하거나 파일을 쓰지 않으므로 재실행해도 기존 상태를 보존합니다. 출력에는 사용자 경로와 설치 식별자가 포함되므로 공유 전 확인하세요.

이 도구는 디스크 목록 점검입니다. 모든 runtime_exposure는 not_checked입니다. 실제 노출과 호출 성공은 아래 절차로 따로 확인해야 하며, 목록 존재를 실행 성공으로 해석하면 안 됩니다.

이번 검증에서는 실제 홈을 두 번 읽어 결과가 동일함을 확인했고, 실행 전후 config.toml의 SHA-256도 같았습니다(스킬 27개, 플러그인 11개, MCP 1개). 격리된 임시 설정 테스트 2개로 비활성 보존, 비밀 값 미출력, 재실행 동일성, 설정 미변경, 설정 부재를 확인했습니다. 현재 세션 도구 이름 검색에서도 image_gen/node_repl/browser/codex_app에 해당하는 도구는 없었습니다. 앱 기능 코드는 변경하지 않아 플레이리스트 앱 전체 테스트는 실행하지 않았습니다.

## 실제 연결 후속 구현과 승인 기준

1. 리드가 AgentCraft 소유 저장소 작업 지원과 범위를 확정합니다. 그 저장소의 검토 가능한 브랜치에서 기존 차단 기본값을 유지하는 서버별 opt-in을 구현합니다. 현재는 이 설정 API가 없습니다.
2. 사용자 설정에서 비활성 항목은 항상 제외하고, 독립 실행과 해당 Codex 버전의 지원이 확인된 MCP만 후보로 삼습니다. 전체 플러그인 활성화나 OFF_FEATURES 일괄 제거는 하지 않습니다.
3. 외부 MCP 호출이 AgentCraft 승인 정책에 도달하는지, 거절 시 실행되지 않는지 테스트합니다. 현재 elicitation은 무조건 decline이고 동적 팀 도구 승인이 외부 MCP 승인까지 보장하지 않습니다. 승인/입력/인증 라우팅과 startup 부작용 확인 전 연결을 제공하지 않습니다. 권한·샌드박스·네트워크 정책을 완화하지 않습니다.
4. 동일 cwd, 선택된 CLI 경로·버전, 실효 CODEX_HOME, 사용자 설정과 thread override를 값 없는 허용 목록으로 비교합니다. checkAuth는 thread override 전 app-server를 실행하므로 시작 단계도 검증합니다. 인증 파일을 복사하지 않습니다.
5. 승인 전 diff와 테스트 결과, 연결 가능한 서버 목록, 남은 미지원 이유를 사용자에게 보여줍니다. 승인 이후에만 확정된 설정을 적용합니다.

## 재시작·적용 확인·롤백

현재 점검 도구는 적용이나 재시작이 필요 없습니다. 공유 스킬을 기존 방식으로 갱신한 뒤에는 새 에이전트 세션에서 목록을 재확인합니다. CLI 경로 또는 호스트 코드 변경은 작업을 저장하고 Foreman을 완전히 종료한 뒤 기존 Codex launcher로 다시 시작해야 합니다. launcher가 기존 프로세스를 재사용할 수 있어 창만 다시 여는 것으로는 충분하지 않습니다.

후속 연결 적용 후 새 세션에서 실제 스킬·도구 명세를 확인하고 승인된 무해한 호출을 한 번 실행합니다. 디스크 설정, 실효 설정, 도구 노출, 호출 성공을 각각 기록합니다. 노출되지 않거나 인증·호스트 조건을 충족하지 못하면 미검증/미지원으로 남깁니다.

이 브랜치의 롤백은 추가 문서와 점검 도구·테스트를 제거하는 것으로 끝납니다. 전역 설정 복구나 인증 복사는 필요 없습니다. 향후 호스트 변경의 롤백은 해당 브랜치 변경을 되돌리고 opt-in을 제거한 뒤 Foreman을 완전히 재시작하여 기존 차단과 명시 비활성이 유지되는지 확인합니다.
